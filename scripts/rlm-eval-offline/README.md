# RLM offline preparation

English | [中文](README.zh.md)

This directory prepares local data, the pinned official OOLONG synth scorer, candidate comparison arms and budget algorithms. It contains no paid launcher. The code loop accepts only scripted fake providers; passing its tests does not establish DSH transport integration, faithful paper reproduction or RLM benefit.

## Local use

Use the existing Python environment with pyarrow and python-dateutil. Run the synthetic acceptance suite with `python3 scripts/rlm-eval-offline/test_offline.py`. It creates temporary synthetic Parquet files, not real OOLONG questions. Code-cell timing uses POSIX signals on the main thread; it is a trusted-fixture limit, not hostile-code isolation.

`prepare_data.py --manifest <local-input.json> --out <new-directory>` reads explicitly named local Parquet fragments. Original-data mode requires the fixed dataset revision and an independently frozen published fragment checksum. Synthetic mode is explicitly labelled in its output. The manifest also supplies exact question IDs and metadata, development/holdout partitions, reviewed dataset-license evidence, a reviewed record-extractor fingerprint, and complete ordered UTF-8 byte ranges with hashes. Missing evidence, omitted tails, conflicting metadata and cross-partition record overlap fail before publishing a freeze. The code MIT license does not establish the dataset’s license. Parquet parsing consumes the exact hash-checked memory bytes, so replacing the source path after verification cannot change the exported rows.

Exports separate the runner field allowlist from controller-only original answer strings. Labelled context never enters runner JSONL. Output hashes bind both files and the original-source metadata. This file split does not prove filesystem/network isolation; the oracle must remain inaccessible to the actual runner before a real trial.

`official_scorer.py --input <controller-input.json> --out <new-result.json>` verifies the complete retained upstream bytes, Git blob and both function ASTs before executing only the original synth extractor/scorer functions. It preserves first-gold, integer numeric, comparison, DATE and case-sensitive behavior. Official content scores and completion-aware scores are separate: incomplete trials retain their official score but contribute zero to the latter. The [upstream source](https://api.github.com/repos/abertsch72/oolong/git/blobs/5c8113ee360957cff010d27310e844630216b21d) identity is recorded in source; the retained base64 bytes decode to the complete original file. OOLONG-Pairs is unsupported until its separate official artifacts are frozen.

## Comparison and budget preparation

The keyless `pilot-receipts.snapshot.ts` example boots the existing Loader composition and actual Worker/Runtime through an in-process scripted adapter. Its four arms retain full-context BM25, complete fixed-chunk map/reduce, external-context no-subcalls and external-context recursive execution separately. Map outputs are read in full through the owning Runtime and enter the root's actual next request. External-context cells request an explicit 64-byte initial fragment; the complete corpus remains in the file. This is not a full-corpus read or an access-isolation guarantee. Python 3 with SQLite FTS5 is required; `DSH_OFFLINE_PYTHON` selects the existing interpreter. Source and plain Node built modes retain separate receipts.

`pilot_receipts.py --bundle <retained-pilot-directory> --out <new-report.json>` verifies the actual request bytes, admission attempts, sends, Worker commands, Runtime cell outcomes, child ownership, complete map inputs/results and unchanged caps. It derives raw output from final Worker text blocks in order. Unknown lifecycle and missing receipts remain in the inventory with exclusion reasons; unknown usage retains its budget reservation. Optional `--source <source-controller> --freeze <frozen-development>` passes only derived terminal outputs to the accepted controller scorer. The report is controller-only. Hashes and same-process observations are not independent signatures. Scripted sends and usage are not HTTP requests, real tokens, cost or measured benefit; all reports keep both launch/readiness flags false. The [decision](../../.agents/notes/implemented/testing/2026-10-18-native-pilot-receipts.md) describes the evidence limits.

`controller_scorer.py --source <source-controller> --freeze <frozen-development> --schedule <schedule.json> --results <raw-results.jsonl> --out <new-report.json>` connects a reviewed local source bundle to scheduled synth outputs. The source directory contains `metadata-reviewed.json` and its five pinned files: `rows.jsonl`, `selection.json`, `source-manifest.json`, `record-map.json` and `extractor.py`. The freeze directory contains `freeze.json`, runner `cases.json` and controller `oracles.json`. This is the fixed local export format, not the separate `prepare_data.py` manifest format. Each result supplies the scheduled `trial_id`, `case_id`, `input_sha256`, recorded `model`, terminal `status` and complete raw `output`. The adapter verifies file fingerprints and original input identities, then calls the pinned official functions with the original answer string. Duplicate, unscheduled, mismatched and unknown-status results fail before writing. Missing trials stay missing; usage is not calculated. Reports include full outputs and gold and therefore belong only to the controller. The [decision](../../.agents/notes/implemented/testing/2026-10-18-scheduled-official-synth-scoring.md) explains why generic extracted-answer scores remain separate.

`arm_adapter.py` defines direct, CodeAct/BM25, CodeAct/subcalls, summary, fixed chunk map/reduce, RLM/no-subcalls, flat RLM and recursive RLM. CodeAct and RLM use the same persistent fake code/file loop, with host-owned none/root-only/recursive spawn policies independent of context placement. RLM initial fake requests contain a context handle and byte count; full original bytes remain accessible in the persistent kernel. Every fake request and code result is retained. Root-only forbids grandchildren; recursive depth and cumulative children are bounded without forced fan-out.

`preprocessing.py` uses local [SQLite FTS5 BM25](https://www.sqlite.org/fts5.html#the_bm25_function), recording SQLite source ID, unicode61, k1=1.2, b=0.75, top-k and query. Original-index ordering resolves score ties. The fixed record packer requires an explicit versioned token counter, retains oversized records whole and preserves every original byte. Summary and fixed map/reduce process all chunks in order, record complete fake inputs and share the same tree budget; a missing or unfinished chunk cannot produce success. Synthetic byte counts are not production model-token proofs.

`budget.py` owns the candidate caps: whole-tree input 200000, output 16000 including reasoning, 24 physical attempts, one in flight, max_tokens 4096, a 1200-second admission window, 64 code cells, 10 seconds per cell, 8192 bytes per material read, depth two and eight cumulative children. Admission reserves before the fake attempt. Unknown usage retains its reservation; known over-reservation usage is charged in full and stops further admission. Quotation refuses missing input, reasoning, transport/WP1 or model evidence and unknown pricing. Conditional arithmetic never grants launch authority.

## Readiness limits

`preflight.py --inputs <preparation-input.json> --out <new-report.json>` writes a new report with the official-source verification, local dependency versions, candidate caps and precise remaining blockers. The example input intentionally contains no real data or prices. Reports always retain `paidLaunchAllowed: false` and `experimentReady: false` for this offline prototype.

Real original Parquet bytes, dataset-license evidence, audited record extraction and real development/holdout question freezing remain external inputs. The actual DSH Worker’s common non-RLM tool loop, provider/template input bound, reasoning-inclusive ceiling, full physical transport/WP1 binding, oracle isolation and model/pricing evidence remain integration requirements. These scripts do not turn the existing request-bytes audit into a proven pre-send token bound. No original run, historical score or installed Desktop is changed.
