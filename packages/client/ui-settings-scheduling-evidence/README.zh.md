# @deepseek-ai/dsh-client-ui-settings-scheduling-evidence

[English](README.md) | 中文

设置中的只读 **调度证据** 页面。每次访问以及点击 **刷新** 时，它通过已认证的 `/scheduling-evidence` RPC 通道请求一份概览，并显示三张卡片和一张表：

- **你的开关：** Radar 证据是否开启、是否同意个人使用采集、分配器的证据模式、生效的 Python 解释器和周期间隔。
- **已存储的数据：** 采集器给出的新鲜度、采集时间和来源最近更新时间、数据年龄、数据版本号、分配器是否已载入该版本，以及 SQLite 各表的行数。
- **最近一次周期：** 开始时间、采集是被跳过、成功还是失败、存储是否读回成功，以及第一条失败信息。
- **模型成绩：** 每一行已存储的模型数据，含通过率、题数、IQ、平均成本和平均耗时。默认只列出分配器能用的 Codex 行；复选框可显示其余行，文本框可按 provider、模型或强度筛选。

Radar 未开启时，页面还会显示开启它所需的设置行。页面本身不修改任何东西：开关在设置文档里，通用设置中的 **打开配置文件** 可以打开它。

## 模型体验

无。本包只在浏览器设置中可视化由 Host 持有的存储，不注册任何面向模型的内容。

#### KV 缓存影响

无；本包既不组装也不发送提供方请求。

## 已知限制与后续工作

- **页面上没有开关：** 开启或关闭 Radar 和个人使用采集需要编辑设置文档；表单行留待后续。
- **每次访问读取一次：** 页面不订阅存储，所以页面打开期间完成的周期要到下次点击刷新才会显示。
- **整表传输：** 每一行已存储的模型数据都会发送并在浏览器中筛选，不分页。
