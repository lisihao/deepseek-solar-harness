# @deepseek-ai/dsh-research-handoff-local

English | [中文](README.zh.md)

The private SQLite library records research run revisions, exact confirmations, immutable external-action inputs and targets, append-only Driver observations, and versioned capture bytes. It performs no website or model request by itself.

## Action ownership

Question, source selection, mode, destination, and plan version form one confirmation binding. Revising any observation clears the confirmation. Generating a Gemini plan is a separate external action from starting research; both require their own recorded input and target.

The action intent commits as `unknown` before its Driver callback runs. A duplicate action only reads the original record. Conflicting input is refused, and an unresolved action prevents bypassing it with another action ID. A Provider-derived logical step also prevents a second action ID from repeating a completed step at the same run revision. Throws preserve unknown and reach the caller. Accepted and completed observations retain stable sequence IDs for reconstructable projections; contradictory terminal evidence is refused. Closing the database does not cancel external research.

Each owned run has one immutable standard-workflow definition and canonical Session identity. Claiming it atomically retains the original question, explicit platform selections, template versions, complete slot values and all four stage identities. Identical starts read the retained definition; another workflow, Session or input for the same run is refused. A new research workflow requires a new run. Definition reads still require the current owner capability; external-action admission remains with the existing action store.

## Complete local artifacts and transfer

Canonical output collection reads only a completed original stage through an explicit trusted Host collector. Each actual observation has an immutable identity; a new partial or complete observation appends a new artifact version, while an identical observation returns the retained artifact. Observation metadata and the original artifact commit in one SQLite transaction and share role-version allocation with ordinary captures. The collector checks the current Host and held Driver before reading; a result from an already admitted call may be retained after revocation, without granting a new read or advancing the workflow.

Capture records retain all supplied UTF-8 bytes in the same run database, including the original action digest, page and conversation observations, extraction method, capture time, and independent complete/partial/unknown extent. A complete capture needs explicit report-end evidence; it does not change the action's processing state or establish factual verification. New role versions append without replacing earlier bytes, and stale concurrent versions are refused. Manual import remains an intermediate capture method.

An owner-scoped read is required before splitting an artifact. SHA-256 identifiers never grant read permission. Explicit byte budgets produce ordered UTF-8 segments with byte ranges, segment counts, part digests, and a full digest. Reassembly rejects missing, duplicated, reordered, or altered segments and retains the original byte order mark and newlines. Local integrity does not prove that a website received these segments or that a model understood them; actual submitted-message and attachment observations require the enclosing Provider and Driver.

## Versioned prompts and exact prepared inputs

The package includes the four original research-design assets with pinned byte digests. Their historical basis text is retained as source material, not a current account or product capability observation. The two v1.0 templates require every named slot explicitly. Rendering replaces only original template slots once, preserves inserted slot-like text, rejects lossy UTF-8, and never truncates. Missing facts must be supplied explicitly by the Host, rather than filled by the renderer.

Host preparation stores the original template, full slot values, exact rendered text and digests before an action. Artifact parts require an owner-scoped read and matching immutable bytes and version. The original question must match the run binding. Preparing input does not confirm the run. A prepared identity cannot change content, and an action referencing it must match its run revision, original question, complete text and stage before the unknown intent commits. Recovery retains old inputs without replay. Direct Host text remains an explicit low-level path; the full workflow Consumer must select the prepared templates. Retention does not prove actual submitted-message or attachment receipt; The Session adapter and actual-action delivery history provide the logging and mapping primitives; complete workflow and UI assembly remain separate work.

## Candidate denominator and judgments

Candidate inventories bind the question digest and immutable report versions. Every changed or retired candidate retains parent/child identities and a reason. Splitting, merging, removing, revising, or downgrading a claim appends a new inventory; it cannot inherit the old denominator confirmation. Confirmation requires a separate trusted control call for the exact current inventory, run revision, and complete latest reports from both stages. New report bytes invalidate it.

Attributed model or human judgments append without overwriting earlier judgments. Their material references identify retained inputs, not independent browser reads. Imported confirmation, completion, or coverage fields are excluded. Neither a confirmed denominator nor a `supported` judgment establishes factual verification, source support, or completed synthesis. The enclosing Provider must supply attribution from the actual input channel.

The first actual Driver qualification is retained against the complete original action digest before the Provider rechecks the grant or submits. Reads preserve observed settings, effort availability, full-input capacity, explicit unavailability, evidence, and local receipt time across reopening. Missing replies remain absent; they are never filled from requested settings. Changing a retained observation, another owner, or damaged durable fields is refused.

Judgment content retains its declared by field, while separate immutable attribution records the current Host policy channel, owner and policy version. Imported attribution and completion fields cannot replace it. This is an assertion by the trusted embedding Host in its broad same-process domain; it is not independent proof of human presence. UI and model Consumers still need to select their correct Host channels.

## Source reads and unresolved operations

Source intents and their exact-URL unresolved check commit atomically in the same SQLite database. Changing a read ID, run revision or Reader cannot bypass an unknown or accepted original read. Another exact URL may proceed. The exact request remains immutable; exceptions preserve unknown. Only an explicit before-visit refusal can record not-admitted. A persisted guard check asserts authorization at that point, not an actual visit.

Initial and redirected visits recheck the live Host callback, original request, current revision and same Reader registration. Late actual acceptance remains attached to the original read after revocation. Observation inspects only its correlated resource; without one it returns the retained unknown state without invoking the Reader. Captures preserve complete supplied UTF-8 bytes and independently distinguish full text, relevant passage, search snippet, title only, unavailable and not observed. These scopes do not establish semantic support. Closing drains owned calls and can remain pending for an adapter that never returns.

## Workflow records

The local Provider implements the research Service Definition with current Host registrations and explicitly registered Drivers. It checks owner-scoped access, complete selection including requested effort, source configuration, original destination, and full-input capacity. Qualification runs after the unknown intent commits; the Driver must recheck the current grant immediately before submission. Revocation prevents new work while correlated late acceptance remains recordable. Provider disposal drains owned calls before closing SQLite and can wait indefinitely for a Driver that never returns.

An embedding workflow Host may add a trusted live-owner check to the same grant. Retained access and existing submission/source/collector guards call it, and the grant is rechecked after the callback. The callback cannot restore an old grant or turn saved IDs into authority. Optional absence preserves raw Host behavior; complete workflow entry and Agent registry ownership belong to the Consumer.

The private pre-release database uses version 19; earlier and unsupported formats are refused without migration. The immutable original target is separate from observed assigned conversation/report identities. Non-null identities cannot change; accepted observations may fill unassigned fields, while completed terminal facts cannot be replaced.

Before any first submission, the guard rechecks the current run revision, complete confirmation digest and confirmed state, plus the original action remaining unknown. A plan revision or independently observed completion blocks an operation that has not submitted. Actual acceptance arriving after submission still belongs to the original action and revision. Execute and observe both require a correlated resource after merging previously retained evidence; accepted/completed durable records with no resource are refused.

Source captures record reading extent independently from complete, partial or unknown completeness; partial or unknown captures require a limitation. A matching text digest cannot replace this observation. A run revision alone does not prevent observing the correlated original resource, but current Host, Reader, source configuration and original-target permissions still apply. Observation neither opens a new page nor rereads the requested URL.

Citation assessments bind the exact inventory digest, current claim text digest, original source read and normalized observation digest. Their nonempty short quotes must match complete UTF-8 byte ranges in retained full-text or relevant-passage captures; URLs, search snippets and titles alone cannot satisfy this source requirement. Capture completeness remains independent and must be inspected by the later completion logic. Relations, source-family dependence and primary-record designations remain attributed judgments. The declared model or human author is separate from the actual Host input channel. Responses append and cannot erase counterevidence; no support count, truth guarantee or verification-complete flag is produced.

Counterevidence dispositions bind the complete original Citation or material-judgment record digest, historical inventory and claim text. Same-target treatment appends with compare-and-swap, retaining all history and allowing explicit reopening as unresolved. Another supported citation does not change that treatment. Explained requires actual Citation evidence; corrected-in-final uses Citation evidence or an explicit finalCorrection mapping reference, and remains an attributed interpretation. Declared author and actual Host input channel persist separately; imported completion fields cannot authorize or settle counterevidence. Disposition records alone provide neither final-report mappings nor current verification completion.

Final mappings append in the same SQLite database with exact run revision, original question, current inventory and complete latest Gemini/ChatGPT report identities. They retain the entire final report and validate UTF-8 locations, candidate coverage, current-text Citation associations, dependency existence and cycle rejection. Retired critical candidates retain their actual change lineage and final revision locations, even without replacements; old incorrect text does not need a supported label. Actual Host channel attribution is separate from the declared author. Same-map retries are immutable and same-run successors use compare-and-swap. The Host separately confirms the exact latest mapping and confirmed denominator; zero critical adopted facts require an explicit applicability reason. Historical confirmations survive while their current validity changes after a new map, report, inventory or run revision. Confirmation can retain unfinished counter-checks and unresolved dispositions; it is not a completed verification decision.

The finalCorrection basis is restricted to corrected-in-final withdrawal of an exact historical target. The append transaction validates the current confirmed map, matching retired inventory version, claim ID, original text digest and report revision location; no final adopted-fact may still use that original text digest. The map exists before its new disposition, and need not list that new disposition ID in reverse. Historical reads retain the fixed mapping association; newer maps or reports cannot make an old withdrawal basis current or trigger fallback to an unrelated Citation. Retained-unresolved stays unresolved, withdrawal supplies no factual support, and withdrawal does not imply process completion.

readFinalStatus recomputes process completeness in one SQLite snapshot. Missing retained original-question text or necessary complete reports yields needs-input; complete reports with absent, stale or unconfirmed mappings yield partial. Every final critical item starts a dependency closure, and each adopted fact in that closure requires a current-text supported Citation backed by a complete full-text or relevant-passage capture. Unfinished critical counter-checks and unresolved exact-target counterevidence block completion. Historical critical removals retain precise report revision locations even without replacements; withdrawal supplies no factual support. Explicit conditional hypotheses and zero-fact applicability reasons never produce a percentage or factual accuracy guarantee.

recordFinalDecision accepts only a new decision identity through the live Host and atomically stores the computed state, complete normalized used records, identities, versions, digests and actual input attribution. Reusing an identity retains its original result. Historical reads verify retained JSON and digests and separately recompute isCurrent; a new counter, unresolved reopening, report, inventory, mapping or revision cannot be hidden by an earlier completed decision. Ordinary limitations and unverified noncritical facts outside the required closure remain visible. Source independence, classification and semantic sufficiency remain attributed judgments; retained questions and material chains do not prove targeted or exhaustive search.

Delivery records share the same SQLite owner but commit after the original action acceptance transaction. A malformed mapping, changed external identity or mapping-write failure cannot roll back accepted or completed action facts, and retry never resubmits the original action. Exact later observation can add a mapping to already completed, unchanged action facts. Historical resource fields may be filled from null; nonempty identities and the external identity for the same run/action/kind cannot be replaced.

Full UTF-8 read-back is compared with the complete original action input without normalization, trimming or digest substitution. Complete text yields matched or mismatched; a partial preview or unavailable content yields not-read-back. Both mismatches and later matches remain in ordered history. Observing an external ID does not establish byte equality, understanding or factual correctness. Attachments here are single UTF-8 text files; binary, PDF, multiple attachments and segmented delivery are not supported. The standard collected-artifact association is checked separately; complete two-stage entry remains Consumer work.

An optional request-specific guard runs before action creation, before qualification, after qualification and through the Driver check immediately before physical I/O. Each invocation receives a detached copy of the same actual request, followed by another current Host check. Late acceptance and delivery are retained before the final request check can refuse advancement. Failure before action creation leaves the fixed action ID unused; failure after unknown intent does not release it for replay.

Workflow previews and their independent confirmations share the original SQLite owner. Creating or reading a preview consumes no prepared-input or action ID. Reads use one database snapshot; a newer material role version, run revision or conflicting frozen input invalidates currentness without rewriting history. Confirmation requires an already confirmed exact run, full preview digest and the current trusted human-entry check. Freezing rechecks these conditions and writes the original prepared prompt in the same transaction, without nested BEGIN or external submission. Prior schema versions 1–18 are rejected without migration.

Standard previews bind the completed original actions, canonical collected material, full delivery history and exact human treatments of previous stages only. Gemini planning requires its complete message before research starts; upload requires the complete collected research report; verification submission requires the completed upload and full attachment match in the original ChatGPT conversation. The verification message has its own full-match gate after submission. Ordinary imported artifacts and newer partial role versions cannot replace the current complete collected output. Full template, slot, artifact ID/version/digest/text and original target associations are checked separately from action completion.

A later complete match of the same external item can supplement not-read-back. Every mismatch remains blocking until a current trusted human entry treats the exact complete negative sequence using a later full same-item match and an explicit reason. Treatments append with same-action compare-and-swap and retain their complete original action, material, history and attribution. New mismatches or changed original material invalidate their current use; additional positive or unreadable observations do not erase negatives or rewrite historical snapshots. Preview confirmation retains its exact preview digest. Dynamic preview checks refuse changed prerequisites before action admission and after asynchronous waits; already observed facts stay under the original action owner. These checks do not establish website compatibility, model understanding or semantic correctness.

readWorkflowState computes original actions, current complete collected outputs, all retained previews, full delivery histories and the existing final verification status in one SQLite read snapshot. Full input delivery, readiness for verification and attributed final verification remain separate fields. Complete reports with an unfinished standard chain cannot inherit a completed raw final status. Standard stage previews select the original templates and canonical material, revise only changed bindings and never confirm or execute an action.

## Model Experience

### Retained research records

#### What the model sees

The local Provider, `LocalResearchHandoffService`, retains full action input and artifacts for the owning Host; it registers no model tool or prompt section.

#### Token effect

This package does not change model requests or token budgets. Full retained inputs increase local storage.

#### KV Cache effect

No model request prefix or KV cache is changed by this storage Provider.
