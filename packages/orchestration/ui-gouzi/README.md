# @deepseek-ai/dsh-ui-gouzi

English | [中文](README.zh.md)

The Gouzi surfaces for the browser. Day to day the user meets the **kennel**: a sidebar row that shows the dogs' faces and how many are awake, and opens (or creates) one chat session composed from the `kennel` agent preset, where a steward agent splits the user's requests across the dogs. Configuration lives in Settings: a **狗子** page lists the long-lived execution members of this main instance and holds the controls to adopt, edit, wake, rest, and retire them. The Host half serves `/api/gouzi` on the same origin as the Web UI; the browser half draws six inline SVG avatars and a five-step adoption wizard (avatar, name, home, role and projects, confirmation). The home step picks the machine the member lives on: this machine, an SSH machine added earlier, or a new one (address, port, user, password). The project step never asks for a typed path: it lists the user's most recently used workspaces as checkboxes (a verified usable recent workspace preselected) and a button that opens the Host's native folder picker; the chosen absolute paths go to `/api/gouzi` as `projects`. On an SSH machine the step browses and checks existing directories on that machine instead.

Opening the kennel keeps the selected workspace and uses a separate chat: it resolves the current session's workspace membership first, otherwise a valid recent workspace or the newest known workspace. It reuses only the latest unarchived `kennel` session belonging to that workspace, preserving each workspace's kennel history separately. If none exists, it awaits the existing [workspace-scoped `sessions.create({ workspaceId })`](../../client/runtime/README.md#new-session-and-the-blank-mirror) operation, applies the preset to that exact created session, records its preset, and then opens it. No workspace reselection is required. Missing workspace, creation failure, or preset rejection reports an error and leaves the original chat selected; rejected composition may leave an ordinary blank session, which is not automatically deleted. The [workspace navigation decision](../../../.agents/notes/implemented/bug-fix/2026-10-04-kennel-workspace-navigation.md) explains why creation does not watch the global current session.

The kennel chat uses a dedicated room with a persistent member and task panel on the right. Its message area owns an independent scrollport, while `conversation.room.composer` renders a separate input area sharing the room’s draft and recipient state. The conversation Root retains the sole mandatory `conversation.composer` chain for Question, PlanReview, Approval, and Readonly interactions. When the session is inert or model-blocked, the room composer declines and the existing InputBar remains available with its unblock controls. A TaskGraph `awaiting_approval` state alone does not create a pending session interaction. “All”, the steward, and member buttons filter the displayed records; filtering never changes the send target. “点名 · 标准任务” selects an explicit member identity and generation for the composer, while clearing that selection sends to the steward. Typed `@name` text alone does not select a recipient. Sending and older-history reads use the room’s explicit session-scoped conversation service, independently of the globally selected chat. An unavailable session or conversation service rejects the operation. The browser preserves the draft and selected target on send failure; a stale room read, changed generation, disabled member, or lack of an available execution entry blocks an addressed send instead of switching recipients.

`GET /api/gouzi?session_id=<session>` returns `GouziRoomSnapshotV1` with the authorized dashboard, current registered execution entries, and only runs whose `admission.sourceSessionId` equals that session. Runs without admission are excluded even when they share a workspace. A task result requires a terminal `node.evidence.accepted` or `node.failed` event for the node’s current attempt and capability generation, a retained evidence reference, and an operator matching the exact attempt’s sealed execution plan. If the run’s durable `admission.gouziRecipient.operatorIds` contains the sealed operator, attribution keeps that admission’s original `gouziId` even after the member changes generation or retires. Without that binding, only a unique current actual registration associates the operator with a member; otherwise the result shows its actual operator id. Results carry the authoritative `OrchestrationEvent.time` and merge with session messages by their recorded times rather than by polling arrival. Missing or mismatched fields leave the result absent, and unknown scheduler states remain visible. `GET /api/gouzi?session_id=<session>&run_id=<run>&evidence_ref=<ref>` returns the actual retained evidence artifact only when the run belongs to that session and a node retains the reference; other references return 404. These authenticated reads preserve existing device scopes and do not dispatch work.

Addressed messages are durable user requests to the steward, not execution receipts. Recipient lookup scans only `user/message` events with `source.kind === 'user'` in the current turn, stopping at `turn/start` or `turn/end`. Plugin, context, and tool messages in the user role cannot clear or replace the human-selected recipient, even when they contain another recipient marker; the latest ordinary human message can clear it. The Host rechecks membership, generation, and actual available execution entries when the orchestration tool starts work. Confirmed recipients constrain every graph node to those entries with no fallback and use standard TaskGraph execution with RLM and Autonomous Mode disabled; direct delegation tools cannot bypass that route. A successful message submission means the request was submitted, not that a task started or passed. Task outputs are labelled “任务结果”, not autonomous member speech. The [room decision](../../../.agents/notes/implemented/feature/2026-10-06-kennel-session-room.md) records the attribution and routing choices.

`GET /api/gouzi` returns `GouziDashboardV1`: the limit of ten, how many members hold a slot, whether this caller may manage, whether this Host can start members, and every member that is not archived. Each member carries `membership`, `connection`, and `activity` plus one `state` reduced by `gouziPrimaryState`: a member outside `enabled` shows its membership, an unreachable member shows that before its last activity, and otherwise the activity shows. `POST` takes a `GouziControlRequest` and requires the `x-dsh-gouzi-control: 1` header; a loopback owner, `cockpit`, and `admin` devices may manage, while `pocket` devices only read and a `gouzi` credential is refused.

`check-projects` accepts `hostId` and a nonempty list of absolute `projects`, inspects existing directories without changing them, pairing hosts, or creating members, and returns `GouziProjectsCheck`: each requested `path` has `usable: true`, or `usable: false` with a `message`. Git repositories, repositories without origin, and ordinary directories are accepted. The picker checks suggestions and newly selected folders before enabling selection; Next requires every selected project to have passed. Pending checks and failed requests cannot authorize a selection. Missing paths, files, and permission refusals produce actionable directory errors; process and timeout failures remain failed requests. Closing the wizard before confirmation does not initialize Git.

Confirmed adoption repeats read-only inspection of every selected directory and checks the ten-member capacity before calling `prepareRepository` sequentially for each distinct resolved source. Preparation initializes Git only when the selected directory is outside a Git repository; it does not stage files, commit, or change origin. `GouziProjectSource` contains an opaque SHA-256 `projectId`, the exact selected real directory `source`, and optional canonical origin metadata `repository`. The first selected project is shown as the default in confirmation and persists as `defaultProjectId`. A preparation failure creates no member or host pairing and consumes no slot; the error lists directories already prepared, whose metadata is preserved. After preparation, adoption pairs the chosen host once, creates the member in `provisioning`, provisions its project map, starts the process, records its endpoint, and enables it. A start failure keeps the slot in `provisioning` and reports `GOUZI_START_FAILED`; waking retries the start. Adoptions run one at a time. Retiring stops the member and its Resident process tree before archival; a working member cannot rest or retire. The [directory adoption decision](../../../.agents/notes/implemented/feature/2026-10-06-gouzi-directory-adoption.md) records execution and recovery semantics.

Adding a machine takes two requests so the user decides about trust before any login. `host-inspect` reads the key the machine presents without logging in and returns its fingerprint. `host-add` carries the fingerprint the user confirmed and the login password; the Provider refuses the machine if the key changed in between, logs in once, installs a dedicated key, and checks that DSH Desktop with the Gouzi agent is installed. The password travels only in that one same-origin request body, is not stored or logged, and is not part of any response. `host-remove` is refused while a live member lives on the host, and `browse` lists one folder level on a host. Every request that names a host needs the same manage permission as adoption.

`GouziHostService` is the Service Definition for hosts and for starting and stopping member processes on them. This package consumes it; the Desktop product provides it. A Server without the service lists members but reports `hostAvailable: false` and refuses adopt, wake, rest, and retire with `GOUZI_HOST_UNAVAILABLE`.

Config: Host `grantDeadlineMs` (default two hours, 60 seconds to 24 hours) is the lifetime of the execution grants issued to every member this panel creates. Host `roomPollIntervalMs` (default 2,000 ms, integer range 250 to 60,000 ms) is included in each successful `GouziRoomSnapshotV1` reply. While subscribed, the browser schedules its next read with that confirmed value; a later failed read retains the last successful interval and snapshot, marking the snapshot stale so it cannot authorize an addressed send. If the first read fails, no interval is known and no automatic timer is scheduled; the room offers “重新读取”. Unsubscribing aborts the read and fences late responses.

## Model Experience

None, as this package adds no independent model request or tool schema; confirmed recipient metadata is carried in the durable user message, and the Host's TaskGraph resolver and delegation guard can return model-visible refusals for addressed work.

#### KV Cache effect

The room projection and display filters remain outside model context. Recipient metadata and guard refusal results use the normal session-history rendering and existing model-request cache behavior.

## Known Limitations and Deferred Work

- The room displays durable user/steward records and attributed task results. Members do not automatically chat with one another. Indeterminate execution requires reconciliation of the original run; the room does not redispatch unknown outcomes.
- A member on an SSH host reaches the main instance through a local SSH port forward and requires Gouzi agent protocol 2 and Remote Sync execution protocol 1.5. An older remote installation is explicitly refused; a version number alone does not prove protocol support. A per-host resource budget and re-pairing of a host belong to later phases.
- Task history is limited to this room’s source session. The room provides no cross-session member history or execution route outside standard TaskGraph nodes.
- The Settings roster is polled every three seconds while open and every twenty seconds otherwise. Room reads use `roomPollIntervalMs`; neither projection subscribes to scheduler events.
