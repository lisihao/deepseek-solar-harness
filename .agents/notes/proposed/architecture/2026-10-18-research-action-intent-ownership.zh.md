# Agent Note: 研究动作意图的所有权

Status: proposed

[English](2026-10-18-research-action-intent-ownership.md) | 中文

## Problem

研究 Provider 需要持久区分动作意图、观察到的接纳和已完成的网站工作。缺少回执不能证明没有提交。因此动作库先把不可变请求及原观察目标以 unknown 提交到数据库，再调用 Driver；重复动作只观察原记录。run 修订与 Provider 派生的逻辑阶段身份共同标识业务操作，不依赖 UI 的尝试 ID。

## Proposal

问题范围、来源配置、所选模式、目的地和计划版本共同形成确认绑定，修订会清除旧确认。持久化保留证据，但不能恢复 Host 执行能力：每次新的外部动作前，Provider 都必须检查当前可信 Host。导入的 policy 和模型内容不能提供这种授权。

同一个 SQLite 事务追加观察并更新动作。稳定的观察序号用于重建 Session/UI 投影，不再建立可独立修改研究状态的第二个所有者。已接纳的工作不能变成 not-sent，终态回执不能被相矛盾的证据替换。关闭本地数据库不表示远端工作已停止。

私有动作库没有组成完整研究能力。Service Definition、当前 Host 授权、完整产物传输、网站 Driver、Session 日志和 UI 仍是完整能力的交付要求。验收需要真实 SQLite 并发与恢复证据、精确确认失效、按 owner 授权读取，以及组装后的 keyless 两阶段流程。真实网站行为必须来自正常可观察界面的证据；仅有 fake 传输不能证明在线兼容性或研究收益。

产物在同一 run 数据库中追加完整 UTF-8 字节及角色版本。采集范围与结束观察独立于动作完成和事实核验。按 owner 授权读取后才进行有明确字节预算的本地传输；哈希与有序分块校验只证明保留字节的完整性，不能授予访问权限或证明网站实际收到内容。私有数据库版本 18 拒绝旧格式，不静默迁移。

候选目录保留原始问题和材料摘要。变更保留父子身份与理由，每个新目录都需要独立的精确分母确认。run 修订或最新报告采集变化会使旧确认失效。模型和人工判断仍是有归属的解释；`supported` 标签和已确认的候选分母都不是独立回源读取证据，也不表示核验完成。后续 Host Provider 负责确认操作及输入通道归属。

当前 Service Definition 与本地 Provider 将访问能力绑定到有效的嵌入 Context 及显式部署策略。请求的模型、模式、推理力度和工具参与不可变动作指纹。资格检查只能在 unknown 意图提交后开始；重入的重复调用不会再次调用 Driver。Host 或 Driver 撤销会阻止新的提交，同时保留实际的迟到接纳。分配的会话与报告身份通过关联证据留存，与原目标分别记录，不能替换已经分配的身份。Provider 处置先等待自身调用结束，再关闭 SQLite；Driver 永不返回时处置可以持续等待。Session 适配器留存逐动作完整输入与动作事实，标准两阶段 Consumer 和 UI 装配仍是独立工作。

实际资格结果按原动作留存一次，并先于授权复查保存，其中包括不可用和未观察到的状态。本地收到结果的时间与网站观察时间分别对待。恢复读取不重放 Driver，也不从请求补造缺失字段。判断 JSON 保留声明的 by 字段，当前 Host 策略另行提供不可变的通道、所有者和策略版本，导入归属不能覆盖它。这属于同进程 Host 声明；独立人工在场及后续 UI/模型输入路由尚未建立。

提交接纳会复查当前 run 修订与确认，并要求原动作仍为 unknown。资格检查返回后，以及 Driver 内部等待结束、提交之前都执行该检查；已经提交的动作随后收到回执时不丢弃。执行和观察均合并原接纳证据，没有资源关联时拒绝 accepted/completed 状态，持久读取执行相同要求。

包内原提示词材料保留字节摘要与历史来源。Host 在动作之前留存完整原模板、全部明确槽位内容、按所有者授权读取的产物版本和渲染文本；替换只扫描原模板。原问题与 run 修订将准备输入绑定到动作，文本或阶段变化会被拒绝。直接 Host 文本仍是显式的底层输入。本地留存不证明外部交付，也不替代待完成的 Session 日志、UI Consumer 与完整流程装配。

来源意图与既有动作共用一个 SQLite 所有者，在调用 Reader 前提交。精确 URL 的未决阻断跨越读取 ID、修订和 Reader 变更；丢回执及无资源恢复均不能导致重新访问。当前 Host 提供 live 授权回调，Reader 必须在内部等待结束后、首次访问及每次跟随重定向前立即调用检查。成功检查只记录当时获准，不代表访问完成。撤销后的已关联迟到接纳仍被保留。捕获正文保留全部提供的 UTF-8 字节及独立读取范围；来源捕获与当前完成计算分别处理。

来源捕获分别记录读取范围与 complete、partial、unknown 完整性；不完整或未知时必须保留限制说明，正文摘要不能替代该状态。run 修订不会单独阻止观察已关联的原资源，但观察仍检查当前 Host、Reader、来源配置和原目标授权；它不打开新页面，也不重新读取原 URL。

引用判断绑定精确目录摘要、当前论断文本摘要、原来源读取和规范化观察摘要。非空短引必须逐字节匹配留存全文或相关原文段中的完整 UTF-8 区间；仅 URL、搜索摘要或标题不能满足实际原文要求。捕获完整性仍独立，后续完成逻辑必须另外检查。引用关系、来源家族依赖和原始权威记录的分类仍是有归属判断；声明的模型或人工作者与当前 Host 的实际输入通道分别记录。响应以追加方式保留，不能删除反证；该记录不产生独立支持计数、事实正确保证或核验完成标志。

反证处置绑定原 Citation 或材料判断的完整记录摘要、历史目录和论断文本。针对同一原目标的处理以 CAS 追加，保留所有历史，允许明确重新保留未解决状态；追加另一条 supported 引用不会改变处置。explained 需要实际 Citation；corrected-in-final 使用 Citation 或明确的 finalCorrection 映射依据，仍属于有归属解释，不是自动语义裁定。声明的作者与当前 Host 输入通道分别持久化；导入完成字段不能授权或解决反证。处置记录本身不提供最终报告映射或当前核验完成状态。

最终映射库保留每个当前候选和精确报告位置，并通过实际目录谱系保留历史关键纠正。删除无法核验的论断而不提供替代项时，记录其撤回，不要求旧命题变成 supported。报告和目录身份使 Host 确认失效可以被观察，同时保留历史。映射确认与动态完成计算分别处理：无环映射及有效字节关联不能证明语义充分、实际定向检索或研究完成。

finalCorrection 只用于精确历史目标的 corrected-in-final 撤回依据。追加与当前已确认映射的校验在同一事务内进行，必须匹配 retired 的目录版本、claimId、原文摘要及报告修订位置，最终所有 adopted-fact 均不能继续采用该原文摘要。映射先存在，处置随后追加；当前映射不必反向列出新处置 ID。历史读取保留固定映射关联，新映射或报告之后不能把旧撤回依据当作当前依据，也不回退到无关 Citation。retained-unresolved 仍保留未解决状态，撤回不提供事实支持；撤回本身不表示流程完成。

当前完成计算与历史决定分别保存，避免旧完成记录遮蔽后来新增的关键反证。读取和决定写入各使用同一 SQLite 快照；当时已用的规范化记录完整留存。当前状态仍依赖精确 Host 映射和有归属解释，不能替代语义判断、实际定向检索、完整 Session 日志或两阶段应用装配。

Session Consumer 将输入意图留存与 Host 动作事实分开，使持久化失败不能被解释为远程未提交。它在调用 Host 前先 flush 固定的完整请求，只有既有 SQLite 所有者决定原动作能否提交。显式 sync 或观察可重建后续证据，不建立另一套执行状态机。此适配器不覆盖原始 Host 调用者，也不替代完整两阶段应用装配。

交付观察与动作接纳分开，使无效或无法写入的关联不能抹掉不重放恢复所需的证据。完整文本相等由保留字节计算，不接收 Driver 自填的匹配标志；外部身份和历史回读差异继续保留，供标准 Consumer 判断。

规范流程身份在归属明确的 run 内唯一，避免通过更换 UI workflow 或 Session ID 再生成一组业务阶段。定义与动作共用数据库，在同一事务中保留完整初始输入；这些元数据不能授予执行权限。新研究使用新 run，原动作所有者继续控制提交。

输出元数据与产物字节共用调用方持有的同一事务，使关联写入失败不会留下孤立产物或消耗角色版本。稳定观察身份区分幂等读取与新的 partial、complete 采集。原 completed 动作事实保持固定，采集不能替换终态事实或启动新研究动作。

live 归属检查位于原 Provider grant 内部，避免 Agent 在 Driver 等待期间被移除或换绑后，仅因外层 Consumer 尚未返回就仍能实际提交。注册器对象身份、Session 归属和已存 ID 分别核对。撤销阻止新访问，已经接纳的原事实仍可留存，不产生替代动作或另一执行所有者。

请求专属有效性检查放在既有提交所有者内部，避免标准预览跨越资格等待时仅依赖更早的外层检查。检查接收实际固定请求，不建立另一接纳状态。即使请求随后失效，已经观察到的接纳仍须持久保存；拒绝推进与证明未提交分别处理。

预览身份不包含可变确认状态，使确认准确 run 不会改变刚供人工审阅的字节。固定准备输入 ID 只在当前预览另行确认后写入，过期预览不能占用这些 ID。已冻结输入保留原身份，不用新的 UI 尝试绕过未知状态。人类输入路由属于当前调用及活跃注册，不能由导入作者标签建立。

前置阶段依据与拟执行阶段分开留存，避免首次提交必须先证明自身未来交付。当前有效性摘要包含原动作和材料身份、精确 mismatch 及人工处置；不可变预览另行保留实际审阅的全部历史。新增正面证据既不丢弃旧 mismatch，也不迫使已冻结动作更换身份。对 mismatch 的处置是有实际归属的人类决定，绑定更晚的同项目精确回读，不认证模型理解或研究事实。

标准协调器读取同一原所有者快照，不从分散缓存的 UI 字段推断完成。人类已审预览、动作接纳、输入全文交付及最终有归属核验分别留存。required 流程事件使完整初始定义和当前状态可重建；持久化失败阻止成功返回，但不能把已接纳操作解释为未提交。无资源 unknown 没有可供观察的原目标，标准 Consumer 保留其不确定性而不调用 Driver。

## Alternatives considered

单次命令取消与嵌入 Host 的存续期各有所有者，因此调用信号贯穿内部持久化和提交等待，但不撤销该 Host。原 Provider 先保留已经接纳的迟到事实，再由 Consumer 拒绝推进。重复调用的等待者只拥有自身等待，不能取消或替换原业务操作。原操作结束且未记录动作时，后来的明确调用可以复用稳定身份；已记录的不确定性始终不能授权重放。成功状态回执标识自身已 flush 的事件，不依赖可变的 Session 最后事件位置。

另设可变流程所有者会把恢复事实与动作接纳分开，因此仍由同一 SQLite 所有者负责。未知提交也不能重放；恢复只读取原动作及其关联资源。

## Acceptance criteria

验收要求包括 SQLite 并发与恢复、精确确认失效、当前所有者访问、可完整重建的输入日志，以及组装后的 keyless 两阶段流程。单个存储单元的源码接受不代表本范围完成。

## Risks

同进程 Host 归属声明不是独立人工在场证明。fake 传输及完整留存字节不证明网站兼容、实际收到、事实正确或研究收益。Driver 永不返回时，处置可能持续等待。
