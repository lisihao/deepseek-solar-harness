# Agent Note: Research action intent ownership

Status: proposed

English | [中文](2026-10-18-research-action-intent-ownership.zh.md)

## Problem

The research Provider needs a durable distinction between recorded intent, observed acceptance, and completed website work. A missing reply cannot establish that a submission did not occur. Its action store therefore commits an immutable request and original observation target as unknown before invoking a Driver, and duplicate actions only observe that record. A run revision and Provider-derived logical step identify the business operation independently of a UI attempt ID.

## Proposal

Question scope, source configuration, selected mode, destination, and plan version form the confirmation binding. A revision clears confirmation. Persistence retains evidence but never reconstructs a Host execution capability: the Provider must check the current trusted Host before any fresh external operation. Imported policy and model content cannot supply that authority.

One SQLite transaction appends an observation and updates its action. Stable observation sequence IDs support rebuilding Session/UI projections without creating a second independently mutable run owner. Accepted work cannot become not-sent, and a terminal receipt cannot be replaced by contradictory evidence. Closing the local database makes no claim that remote work stopped.

The private action library does not compose the complete research capability. Service Definition, current Host authorization, complete artifact transfer, website Drivers, Session logging, and UI remain obligations of that capability. Acceptance requires real SQLite concurrency and recovery evidence, exact confirmation invalidation, owner-scoped reads, and an assembled keyless two-stage flow. Real website behavior requires normal observable interface evidence; fake transport alone cannot establish live compatibility or research benefit.

Artifacts append exact UTF-8 bytes and role versions in the same run database. Capture extent and end observations stay independent of action completion and factual verification. Owner-scoped reads precede local byte-budgeted transfer; hashes and ordered segment validation establish retained-byte integrity without granting access or proving actual website receipt. Private database version 18 refuses prior formats rather than silently migrating them.

Candidate inventories retain their original question and material digests. Changes preserve parent/child identities and reasons, and each new inventory needs its own exact denominator confirmation. Changed run revisions or latest report captures invalidate that confirmation. Model and human judgments remain attributed interpretations; neither supported labels nor a confirmed candidate denominator provide independent source-read evidence or completed verification. The current Host Provider owns confirmation and input-channel attribution.

The current Service Definition and local Provider bind access to a live embedding Context with explicit deployment policy. Requested model, mode, effort, and tools participate in the immutable action fingerprint. Qualification starts only after the unknown intent commits; reentrant duplicates do not invoke the Driver again. Host or Driver revocation prevents fresh submission, while actual late acceptance is retained. Assigned conversation and report identities append correlation evidence independently of the original target and cannot replace a previously assigned identity. Provider disposal waits for owned calls before closing SQLite; a never-returning Driver can keep disposal pending. The Session adapter retains complete per-action inputs and action facts; the standard two-stage Consumer and UI assembly remain separate work.

Actual qualification results persist once against their original action before rechecking the grant, including unavailable and unobserved states. Local receipt time is distinct from a website observation time. Recovery reads neither replay a Driver nor fill missing fields from the request. Judgment JSON keeps its declared by field, while the current Host policy supplies a separate immutable channel, owner and policy version. Imported attribution cannot override that record. This is a same-process Host assertion; independent human presence and the eventual UI/model input routes are not yet established.

Submission admission rechecks current run revision and confirmation, and the original action must still be unknown. This check applies after qualification and after Driver-internal waits immediately before submission; it does not discard a receipt for an effect already submitted. Both execution and observation merge original acceptance evidence and refuse accepted/completed state without a correlated resource. Durable reads enforce the same resource requirement.

The bundled original prompt assets keep their byte digests and historical provenance. Host preparation stores the complete original template, every explicit slot value, owner-readable artifact versions and rendered text before an action. Replacement scans only the original template. The original question and run revision bind prepared input to its action; changed text or stage is refused. Direct Host text remains an explicit lower-level input. Local retention neither proves external delivery nor replaces the pending Session log, UI Consumer and assembled full workflow.

Source intents share the existing SQLite owner and commit before Reader invocation. An unresolved exact URL is fenced across request IDs, revisions and Reader changes; lost replies and no-resource recovery never cause a new visit. The current Host supplies a live authorization callback, and a Reader must call its guard immediately before each initial or redirected visit, after internal waits. Successful guards record authorization checks, not visit completion. Correlated late acceptance survives revocation. Capture text retains full supplied UTF-8 bytes and an independent extent; source capture and current completion calculation remain separate.

Source captures record reading extent independently from complete, partial or unknown completeness; partial or unknown captures require a limitation. A matching text digest cannot replace this observation. A run revision alone does not prevent observing the correlated original resource, but current Host, Reader, source configuration and original-target permissions still apply. Observation neither opens a new page nor rereads the requested URL.

Citation assessments bind the exact inventory digest, current claim text digest, original source read and normalized observation digest. Their nonempty short quotes must match complete UTF-8 byte ranges in retained full-text or relevant-passage captures; URLs, search snippets and titles alone cannot satisfy this source requirement. Capture completeness remains independent and must be inspected by the later completion logic. Relations, source-family dependence and primary-record designations remain attributed judgments. The declared model or human author is separate from the actual Host input channel. Responses append and cannot erase counterevidence; no support count, truth guarantee or verification-complete flag is produced.

Counterevidence dispositions bind the complete original Citation or material-judgment record digest, historical inventory and claim text. Same-target treatment appends with compare-and-swap, retaining all history and allowing explicit reopening as unresolved. Another supported citation does not change that treatment. Explained requires actual Citation evidence; corrected-in-final uses Citation evidence or an explicit finalCorrection mapping reference, and remains an attributed interpretation. Declared author and actual Host input channel persist separately; imported completion fields cannot authorize or settle counterevidence. Disposition records alone provide neither final-report mappings nor current verification completion.

The final mapping store retains every current candidate and exact report location, while historical critical corrections remain visible through actual inventory lineage. Removing an uncertain claim without a replacement records its withdrawal rather than requiring the old proposition to become supported. Report and inventory identities make Host confirmation invalidation observable without rewriting history. Confirmation is deliberately separate from the dynamic completion calculation: an acyclic mapping and valid byte association cannot establish semantic sufficiency, actual targeted search, or completed research.

The finalCorrection basis is restricted to corrected-in-final withdrawal of an exact historical target. The append transaction validates the current confirmed map, matching retired inventory version, claim ID, original text digest and report revision location; no final adopted-fact may still use that original text digest. The map exists before its new disposition, and need not list that new disposition ID in reverse. Historical reads retain the fixed mapping association; newer maps or reports cannot make an old withdrawal basis current or trigger fallback to an unrelated Citation. Retained-unresolved stays unresolved, withdrawal supplies no factual support, and withdrawal does not imply process completion.

Current computation and historical decisions remain separate so earlier completion cannot mask later critical counterevidence. Each read or decision write uses one SQLite snapshot and retains complete normalized records used at that time. Current status still depends on exact Host mappings and attributed interpretation; it cannot replace semantic judgment, actual targeted search, complete Session logging or two-stage application assembly.

The Session Consumer separates retained input intention from Host action facts so persistence failure cannot be interpreted as remote non-submission. It flushes the fixed full request before calling the Host, while the existing SQLite owner alone decides whether an original action may submit. Explicit sync or observation reconstructs later evidence without creating another execution state machine. The adapter does not cover raw Host callers or replace full two-stage application composition.

Delivery observations remain separate from action acceptance so an invalid or unwritable association cannot erase the evidence needed to recover without replay. Complete text equality is computed from retained bytes rather than accepted from Driver flags; external identity and historical read-back differences remain available for the standard Consumer to assess.

Canonical workflow identity is unique per owned run so changing UI workflow or Session IDs cannot create another set of business stages. The definition shares the action database and atomically retains full initial inputs; its metadata grants no execution authority. New research uses a new run, and the original action owner continues to control submission.

Output metadata and artifact bytes share one caller-owned transaction so failed association writes cannot leave an orphan capture or consume a role version. Stable observation identities separate idempotent reads from new partial or complete captures. The original completed-action facts remain fixed; collection has no permission to replace them or start a new research action.

Live ownership is checked inside the original Provider grant so an Agent removed or rebound during a Driver wait cannot reach a fresh submission merely because an outer Consumer has not returned yet. Registry object identity and Session ownership remain distinct from saved IDs. Revocation stops new access, while already admitted original facts remain recordable without a replacement action or another execution owner.

Request-specific validity is checked inside the existing submission owner so a standard preview cannot rely solely on an earlier outer check across qualification waits. The check receives the actual fixed request and does not create another admission state. Already observed acceptance stays durable even when later request validity fails; refusal to advance and proof of non-submission remain distinct.

Preview identity excludes mutable confirmation so confirming an exact run cannot invalidate the bytes a human has just reviewed. Fixed prepared IDs are written only after a current preview is separately confirmed, and stale previews cannot consume those IDs. Frozen inputs keep their original identity instead of using a new UI attempt to bypass uncertainty. Human routing belongs to the current invocation and live registration, not an imported author label.

Previous-stage evidence is retained separately from the proposed stage so a first submission never depends on its own future delivery. A stable currentness key includes original action and material identities, exact mismatches and their human treatment, while the immutable preview retains the complete history actually reviewed. Additional positive evidence does not silently discard old mismatches or force a frozen action to acquire a new identity. Treating a mismatch is an attributed human decision tied to a later exact same-item read-back; it does not certify model understanding or research truth.

The standard coordinator reads one original-owner snapshot instead of deriving completion from disconnected cached UI fields. Human-reviewed previews, action acceptance, full input delivery and final attributed verification remain distinct records. Required workflow events make the complete initial definition and current state reconstructable; persistence failure prevents a success return but cannot reinterpret an accepted operation as unsubmitted. No-resource unknown has no original target to observe, so the standard Consumer retains its uncertainty without calling a Driver.

## Alternatives considered

One command's cancellation and the embedding Host's lifetime have different owners. Per-call signals therefore follow internal persistence and submission waits without revoking that Host. The original Provider retains admitted late facts before the Consumer refuses advancement. A waiting duplicate owns only its own wait; it cannot cancel or replace the original business operation. Once an operation settles without recording an action, a later explicit call can reuse its stable identity, while recorded uncertainty never authorizes replay. Each successful state receipt identifies its own flushed event rather than relying on the mutable position of the latest Session event.

A second mutable workflow owner would separate recovery facts from action admission. The design retains one SQLite owner instead. Replaying an unknown submission is also excluded: recovery reads the original action and its correlated resource.

## Acceptance criteria

Acceptance requires SQLite concurrency and recovery, exact confirmation invalidation, current owner access, complete reconstructable input logs and an assembled keyless two-stage flow. Source acceptance of a storage unit alone does not complete this scope.

## Risks

Same-process Host attribution does not independently prove human presence. Fake transport and complete retained bytes do not establish website compatibility, actual receipt, factual truth or research benefit. A Driver that never returns can keep disposal pending.
