# Agent Note: DSH Desktop 3.14.0 协作可观测性检查点

Status: proposed

[English](2026-09-04-dsh-desktop-3-14-0-collaboration-observability.md) | 中文

## 问题

3.14.0 交付同时改变多个用户可见的协作界面：Debate、物理算子轨迹、治理证据、计费分类、私有记忆、Synapse 导航和 Agent Team 边界。这些界面共享事件与模型路由，因此一个投影可能看似完整，却仍然缺少 Provider 结果、把费用记入错误账本，或者混淆执行与治理。现有 Debate transcript、Synapse session map、原生订阅路由以及 Prime/RLM 记录仍分别拥有各自决策的权威；本检查点只记录本次发布的验收边界和当前交付状态，不取代它们。

## 方案

本次发布使用明确且有界的投影，并为每类事实保留唯一权威。

- Debate 只有一个逻辑 Desktop 实例。启动或查看 Run 不得启动额外可见的 DSH Desktop 应用，也不得把辅助进程暴露成第二个 Dock 项目。
- 名册使用语义化 HTML 表格，展示面向人的角色名、职责、算子、模型和状态。内部角色 id、原始标签和技术细节只放在可选的详情视图中。
- 标准 Debate 使用多轮预算，并在派发前准入后续轮次，同时报告真实的停止原因。明确的简洁请求可以有意使用一轮紧凑流程，但不能被标记成意外的预算失败。
- Provider 身份要把 `claude-fable-5[1m]` 这类原生模型变体与真实回退区分开。只有选中的 Provider 发生改变时才显示回退，原因放在技术详情中。
- Debate 是执行路由，不能覆盖持久的主模型选择器。Run 结束后，用户选择的模型和协作偏好必须保持不变。
- 使用 Codex 或 Claude Code 订阅的 Debate 调用不计入 DeepSeek API 账本。DeepSeek API 调用仍然计费，账本通过明确的重新计价规则移除历史错误费用。
- 治理 Trace 展示准入、路由、scope、审批、租约、receipt、重试、Evidence 和交付决策。普通轨迹展示执行进度、工具调用、公开输出、Debate 楼层和用量；两个投影相互关联，但不重复同一条事件流。
- DSH Mnemon 只在本地保存稳定的用户偏好和项目规则。写入的记忆排除凭据、网络标识、原始会话、临时进展和受源代码管理的私有数据；任何私有记忆文件都不得进入 GitHub 源码或发布产物。
- Synapse 的会话地图控件注册在 DSH 对话操作区，放在任务编排和 Debate 控件旁边。上游可视化地图仍是可卸载投影，不能成为执行权威。
- Debate 面板遵循 BBS 式阅读顺序：主题、状态、参与者表、逐轮楼层、主张与证据、主持人总结、异议和用量。长内容使用易读卡片和有界滚动，不显示原始 Markdown 表格或无结构字符串。
- Agent Team 继续作为面向用户的角色与邮箱体验，而单一 TaskGraph Scheduler 继续负责 DAG 就绪、并行、scope 冲突、重试、配额和 Evidence。发布记录有效限制，不宣称无限集群能力。
- 物理算子输出包含有界的公开进展、原生 Provider/模型身份、工具调用/结果摘要、用量、工件和错误。它不暴露私有推理，也不把摘要占位符当成完整原生轨迹。

当前实现仍在进行中。3.14.0 源码工作树尚未完成 L3 Desktop 门禁，尚未安装为验收发布版本；在源码、产物、运行版本和远端提交证据一致之前，不得称其已经发布。

## 已考虑的替代方案

**把所有协作事件放进普通轨迹。** 不采纳，因为治理决策回答工作为何被准入或阻断，普通轨迹回答执行做了什么；合并后两个视图都会冗余，并且权威边界不清楚。

**在浏览器中直接渲染 Provider id 和 Markdown 表格。** 不采纳，因为原始 id、回退内部信息、标签和用竖线分隔的表格是实现输出，不是可用的参与者或讨论视图。语义元素能保留相同事实，同时改善可读性和无障碍能力。

**每次相关改动后都运行完整的真实订阅和 API 测试。** 不采纳，因为受影响约定与输入不变时，这只会消耗配额而不增加证据。开发阶段使用离线 fixture 与受影响的聚焦检查；稳定的 L3 构建完成后只执行一次最小真实订阅验收。

**让 Agent Team 或 Debate 成为独立的全局调度器。** 不采纳，因为第二个权威可能与 TaskGraph 的状态、租约、重试、配额和完成证据竞争。它们继续消费共享 Scheduler 和物理算子接缝。

## 验收标准

- Debate 启动和查看流程只留下一个可见 Desktop 应用，编排或 Resident 辅助进程不会显示为第二个 Dock 应用。
- 新 Debate 原样显示用户主题、真实的语义名册表格、可读的逐轮卡片和主持人总结，不出现原始标签或竖线表格文本。
- 标准 Run 在预算准入允许时能够启动配置的后续轮次；简洁 Run 记录有意采用的一轮策略；每个终态都写明真实停止原因。
- Fable 等原生别名不会显示错误回退；真正的 Opus 到 Codex 回退会显示发生变化的 Provider 和原因。
- 主模型选择器在 Debate 运行前、运行中和运行后都保留用户选择。
- 只有 Codex 或只有 Claude 的订阅 Debate 不增加 DeepSeek API 用量或费用，而 DeepSeek API 调用仍然出现在 API 账本中。
- 治理 Trace 只包含治理决策和证据，普通轨迹包含执行细节；两个视图都不能只是另一个视图改名后的副本。
- Mnemon 重启后能够重新读取写入的稳定偏好；私有路径不被 Git 跟踪；存储条目和发布树中不存在凭据或原始会话材料。
- Synapse 会话地图控件在支持的窗口宽度下放在编排和 Debate 控件旁边且不重叠；移除 Synapse 后普通会话仍可用。
- Debate 详情在桌面和窄窗口下都保持可读，保留轮次和楼层顺序，让技术字段处于次要层级，并为状态和控件提供无障碍标签。
- Agent Team、Debate 和 TaskGraph 报告配置的参与者、成员、Provider 与并行容量限制；只有 TaskGraph 负责跨 Run 调度和 scope 冲突解决。
- 物理算子 Debate 或直接回合在重新加载后仍能在轨迹中显示所有可用的有界公开 Provider 事件、原生身份、工具结果、用量、工件和错误，并排除私有推理。
- 最终 L3 交付分配新的稳定版本，构建精确的源码提交，在 MacBook 安装验收应用，验证显示/运行/产物版本一致和 HTTP 健康，并在声称完成前核验推送后的远端 SHA。

## 风险

- 原生订阅资格可能因产品认证或网络状态失败。界面必须展示真实 Provider 错误，不得静默改用 DeepSeek API 路由。
- 增强公开轨迹可能泄露过多数据或放大会话日志。投影保持有界，需要时使用内容寻址工件，并排除私有 prompt、隐藏推理、凭据和完整终端文本。
- 预算准入和 Provider 容量可能让 Debate 在达到请求的最大轮次前停止。结果必须区分有意的简洁策略、配额耗尽、Provider 失败和收敛，不能全部显示为同一个标签。
- 私有 Mnemon 数据可能被打包或宽泛的仓库命令意外复制。本地存储和发布检查必须确保它不在受跟踪源码和生成产物中。
- 发布仍依赖先合并所有并行工作树改动，再执行唯一的最终门禁。在完成该合并和 L3 运行证据前，本记录保持为正在进行的 proposed 检查点。
