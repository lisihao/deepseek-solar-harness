# Agent Note: Resident 资格探测与诊断投影隔离

Status: implemented

[English](2026-08-20-resident-qualification-and-diagnostic-projection.md) | 中文

## 问题

Resident 会话轮询复用了 `operator.list`，因此读取持久会话状态也会启动原生产品资格探测。多个面板消费方可能让这些启动互相重叠，而 Claude Code 资格探测本身还会并发启动版本、认证与模型目录探测。一个只读用户界面因而反复、并发地触及 macOS 订阅凭据路径。与此同时，临时 `dsh-orchestration-*` 工作区中的持久化编排验收 fixture（测试前置数据）也会和用户任务并列展示，尽管其刻意失败属于测试证据而非用户工作。

## 决策

Resident 控制协议版本 4 将 `session.list` 与 `operator.list` 分开。会话读取只返回 daemon 的存储投影，绝不探测原生产品资格。daemon 按 operator id 合并并发资格探测，不同产品 Driver 仍相互独立。Claude Code 资格探测按顺序执行版本探测、订阅状态探测和模型目录探测；只有确认 CLI 版本符合预期且存在原生订阅后，才开始发现模型。

编排面板会从未选择具体任务的列表中排除规范化工作区位于 `/tmp/dsh-orchestration-*` 或 `/private/tmp/dsh-orchestration-*` 的运行。持久化运行及其证据仍然保留，显式指定 `run_id` 仍可检查它。普通项目路径绝不会按标题、失败代码或任务内容分类。

## 验证

daemon 测试固定了握手后的会话列表不会增加资格探测次数，并且重叠的提供方读取共享同一个进行中的资格探测。展示测试固定了狭窄的临时工作区分类，同时保留普通项目。打包后的 Desktop 验证会从同一源提交中运行封装的 Resident 与编排包。

## 考虑过的替代方案

**降低面板轮询频率。** 更慢的间隔仍会让会话读取产生认证副作用，也仍允许独立消费方互相重叠。

**在进程生命周期内缓存提供方状态。** 这能避免重复探测，却会让登录、退出、版本与模型可用性在 daemon 重启前保持陈旧。

**删除失败的验收运行。** 删除会移除有用的持久测试证据，并让展示策略与存储修改耦合；按路径过滤既保留证据的可检查性，又不把它展示为用户工作。

## 后果

会话活动可以保持新鲜而不触及原生凭据。提供方状态刷新仍会观察当前原生态，但同时发生的请求共享一次资格探测，Claude Code 也绝不会并发运行自身涉及凭据的探测。协议版本 4 会有意拒绝旧 daemon 的方法集，而持久化状态 schema 仍为版本 3。诊断过滤依赖专用临时工作区约定，因此期望运行不出现在默认面板中的验收工具必须继续遵守该约定。
