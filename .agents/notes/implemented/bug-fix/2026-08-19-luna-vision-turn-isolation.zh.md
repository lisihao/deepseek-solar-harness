# Agent Note: Luna 识图轮次隔离

Status: implemented

[English](2026-08-19-luna-vision-turn-isolation.md) | 中文

## 问题

Luna Vision Bridge 必须使用当前用户已认证的 Codex 订阅完成图片转写，同时不能把这次转写变成完整的 coding agent（编程智能体）运行。继承用户配置、仓库说明、skills、plugins、apps 和工具会扩大模型上下文，允许无关工具调用，并让单张图片转写依赖周围的开发 harness。设置表单也无法在视觉上区分成功保存与点击未生效。

## 决策

内置 Luna 启动器保留当前 Codex 认证，以选定图片和转写提示词启动临时、只读的 Codex 轮次。它忽略用户配置和仓库规则，排除项目、应用、协作、环境与权限说明，并关闭 skill 注入、plugins、apps、工具发现、执行工具、钩子、记忆及无关多模态设施。该轮次不含模型可见的开发 harness，只返回由 Host 适配器消费的 JSONL 响应。

设置区在 `settings.update` 或恢复默认值的 `settings.mutate` 成功后显示实时状态消息。编辑任意字段会清除先前的成功消息，因此消息始终描述当前显示的草稿。

## 验证

启动器测试捕获完整 Codex 参数并要求包含隔离开关。客户端测试通过设置 API 保存修改后的下游目标并恢复默认值，随后要求出现对应的实时状态消息。安装包验收使用真实受支持图片运行已安装启动器，确认 Luna 返回描述且没有 shell 或其他工具调用。

## 考虑过的替代方案

**继承用户的完整 Codex 环境。** 这种做法把 coding harness 用于狭窄的识图轮次，会注入无关说明和 skills，并可能触发工具或过量上下文用量。

**使用 API key 调用 OpenAI API。** 这种做法会改变产品的认证与计费约定；该桥接插件有意使用用户已登录的 Codex 订阅。

**成功写入后保持静默。** API 会即时应用设置，但静默表单无法区分成功与控件无响应，导致用户重复执行有效操作。

## 后果

图片转写继续使用订阅认证，同时不再依赖用户的编程配置和可用工具。设置持久化无需重启即可被观察。后续 Codex CLI 版本必须继续支持安装包插件使用的启动参数；聚焦启动器测试会在发布前发现参数缺失，已安装图片验收会发现不兼容的运行时行为。
