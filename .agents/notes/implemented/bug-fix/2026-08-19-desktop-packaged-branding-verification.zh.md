# Agent Note：Desktop 安装包品牌标识验证

状态：已实现

[English](2026-08-19-desktop-packaged-branding-verification.md) | 中文

## 问题

仅靠源码测试无法证明可安装的 Desktop 应用包含当前 Solar 品牌标识实现。即使检出的源码已将产品标识挂载到窗口内容下方，由陈旧或外来构建产物组装的安装包仍可能重新引入旧左侧栏标识。

## 决策

Electron Builder 的 `afterPack` 门禁检查每个 Desktop 应用实际生成的 `app.asar.unpacked/lib/client.js`。该 bundle 必须包含底栏安装器和 body 空间预留标记，并且不得包含旧侧栏标识。内容缺失、不可读取或包含禁用标记时，打包会在签名前失败。

已安装应用验收还会检查运行中 Web profile 实际提供的 Client bundle 与实时 DOM。可接受的界面只包含一个 body 层级的产品标识，侧栏内没有品牌入口，并显示与源码清单及应用包一致的稳定版本。

## 验证

聚焦测试覆盖有效安装包内容、每个必需底栏标记和每个禁用旧标记。打包钩子在签名前对已完成的平台应用执行同一验证器。

## 考虑过的替代方案

**只依赖 Client 源码测试。** 这类测试无法发现另一个仓库或陈旧产物在源码检查通过后替换应用。

**只检查应用版本。** 两个安装包可以使用相同 SemVer 却包含不同 Client bundle，因此版本一致不能证明品牌实现一致。

**只在发布后检查安装包文件。** 发布后告警仍允许已知无效的产物存在；关闭式打包门禁会阻止其进入签名阶段。

## 后果

Desktop 打包现在把底部产品标识视为产物级契约。任何有意的品牌实现变更都必须同步更新必需与禁用的 bundle 标记、聚焦测试和已安装应用实时验收。
