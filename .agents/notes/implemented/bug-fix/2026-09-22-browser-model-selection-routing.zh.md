# Agent Note: 浏览器算子路由使用统一模型选择

Status: implemented

[English](2026-09-22-browser-model-selection-routing.md) | 中文

## 问题

浏览器模型选择器维护可变的会话选择，物理算子路由却可能仍读取 agent（智能体）的创建选项。因此，以 Claude Code 创建的会话可能显示 ChatGPT Web，却尝试检查 Claude 登录资格。另存的协作偏好又让这种冲突状态看起来像是有意配置。

## 决策

Agent 负责保存每次提示组装捕获的模型选择。物理算子路由读取同一份已捕获选择；未安装模型选择的入口继续使用配置的 Agent 默认值。组装期间发生的模型切换在下一步骤生效。选择普通提供方后，不继承过时的物理算子默认值。

协作控件订阅模型选择器已有的会话目录。物理主模型生效时决定路线标签并停用冲突的协作选择；只有对应的原生产品提供模型偏好。ChatGPT Web 隐藏原生模型控件并停用资格轮询。用户切回普通主模型时，仍可使用之前保存的协作偏好。显式 Debate 模式保持明确区分。

## 考虑过的替代方案

**每次切换浏览器模型时修改 Agent 创建选项。** 这会增加重复的选择所有者，并破坏提示组装和请求配置已有的逐步骤快照语义。

**只隐藏 Claude 选择器。** 界面显示无法阻止服务端使用过时路由，也不能保护其他客户端提交的请求。

**每次切换模型时清除已保存的协作偏好。** 这会丢弃独立的用户偏好，而不是推导当前哪些控件适用。

## 影响

浏览器选择、提示变量和物理派发在已准入的步骤中保持一致。该修改不改变原生认证，也不会静默选择备用提供方。浏览器操作仍是临时执行，不获得原生工具桥。

回归证据包含真实 Loader 组合：先创建 Claude 会话，再通过会话模型选择 API 切换到 ChatGPT Web，随后发送简短的身份问题。外部提供方计数器证明浏览器只被调用一次，Claude 从未被检查资格或启动。
