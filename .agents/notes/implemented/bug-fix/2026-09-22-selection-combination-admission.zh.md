# Agent Note: 适用的执行选择与准入

Status: implemented

[English](2026-09-22-selection-combination-admission.md) | 中文

## Problem

独立的主模型、协作和 TaskGraph 偏好可能同时显示为生效，实际却只有一种设置决定执行。成功的命令传输可能掩盖保存被拒绝，不支持的原生模型配置可能直到调度才失败，显式自主执行也可能与禁用 RLM 冲突。直接 Debate 还缺少 Plan 的审核与退出流程。

## Decision

协作控件从共享模型目录推导当前算子，保留未生效的偏好而不把它们显示为有效设置。原生模型控件属于选中的原生产品，或普通主模型的首选协作者。Debate 接管直接消息；Debate 或纯浏览器主模型期间，TaskGraph 策略设置保持未生效。RLM 设置描述图节点，而不承诺直接消息的执行者。

Host 命令在追加偏好前，使用所选算子的实时目录验证原生模型与强度组合。清除配置不要求资格检查。命令处理器拒绝会停止多步选择器切换。保存偏好和图准入都要求显式自主执行配合启用或自动 RLM；选择标准模式会关闭显式自主执行。直接 Debate 拒绝活动的 Plan，而模型调用的 Debate 工具仍可用于普通 Plan 审核流程。

任务模板匹配与路由读取同一个已捕获的模型选择。Claude 认证将原生 CLI 的结构化未登录响应视为认证状态，即使进程结果为非零；其他进程失败仍保留为错误。浏览器提交拒绝已有草稿，而不替换用户输入。

## Alternatives considered

**切换模型时清除所有偏好。** 这会丢失有效的已保存选择，并混淆未生效状态与无效值。

**禁止所有跨模型协作。** 普通 API 模型可以合理地委派给原生协作者。界面仅约束当前执行路径无法使用的设置。

**只信任禁用控件。** 其他客户端和持久状态可以绕过界面，因此命令与执行准入保留各自检查。

## Consequences

用户可以识别当前路由、恢复过期模型配置，并在开始执行前看到保存失败。现有日志仍可读取；冲突策略在准入时失败，不会被静默改写。Plan 仍是独立于沙盒和审批设置的指导。浏览器草稿保护不提供持久发送回执或续接恢复，认证分类也不能证明原生账号为何退出登录。
