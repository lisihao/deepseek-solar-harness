# Agent Note: 按工作区打开狗窝

Status: implemented

[English](2026-10-04-kennel-workspace-navigation.md) | 中文

## 问题

狗窝是使用已选工作区的独立聊天。在所有会话中搜索狗窝可能打开另一个工作区的狗窝。通过无返回值的启动操作创建会话，再监听全局当前会话，会丢失所请求结果的身份：其他导航可能满足空白会话监听条件，而没有明确工作区的启动可能让用户再次选择工作区。

## 决策

[狗窝导航拥有者](../../../../packages/orchestration/ui-gouzi/README.md)按当前会话所属关系确定目标工作区，只有未选工作区时才依次回退到仍然有效的最近工作区和最新的已知工作区。复用范围只包含目标工作区中最近更新且未归档的狗窝会话。其他工作区的历史分别保留。

浏览器外部 `ISessions` 接口显式声明工作区范围的 `create({ workspaceId })`，复用现有实现与写入者。创建流程向 [`SessionRuntime.create`](../../../../packages/client/runtime/src/client/sessions/service.ts) 操作明确传入工作区 id 并等待完成；返回 id 标识新创建的会话，操作完成时其列表条目与工作区绑定已可用。狗窝先为该返回会话应用并记录预设，再打开它。这复用运行时已有的会话创建保证，而不是从全局当前会话变化推断身份。创建和组成会话成功前，原聊天保持选中；缺少目标、创建失败或预设被拒绝时会报告错误，不清空原选中状态。组成会话失败可能留下普通空白会话；导航不会自动删除它。

## 考虑过的替代方案

**复用所有工作区中最近的狗窝。** 这可能悄悄把已选工作区换成另一个工作区的狗窝，并混淆导航历史。因此复用按工作区所属关系限定。

**启动会话后不等待其身份，而观察任何当前空白会话。** 全局监听可能把预设绑定到无关导航的结果，也可能在创建后超时，却无法证明它等待的是哪一个会话。现有的有类型定义的创建结果提供精确会话身份，通过对现有操作的显式声明提供给消费方；`connectWorkspace` 可能复用原会话或无关的普通空白会话，而非创建独立聊天。

**创建狗窝或选择预设前清空原聊天。** 失败会让用户失去原选中状态，并可能需要再次选择工作区。只在会话组成成功后打开它，能在失败时保留当前聊天。

## 影响

点击狗窝会沿用已选工作区，不要求用户再次选择。每个工作区保留自己的狗窝对话；狗窝仍是通过现有预设组成的普通会话。这改变浏览器导航，并在 `ISessions` 上显式声明现有的工作区 create 操作；创建实现与写入者不变，也不增加第二个 Scheduler。

有类型定义的创建结果确定的是会话身份，不是任务执行或验收。此决策不证明已安装 UI 的行为、实际 GUI 验收，或远程原生 worker 读取了仓库内容。
