# Agent Note: 狗窝任务图派单

Status: implemented

[English](2026-10-04-kennel-taskgraph-dispatch.md) | 中文

## Problem

狗窝总管可能构造不完整的任务图，收到 `GRAPH_INVALID` 后，又通过 `physical_operator` 调用同一个狗子 ID。该工具的宿主注册表不负责狗子的 TaskGraph 执行，因此第二次失败可能被误报为成员连接故障。

## Decision

编排工具使用真实图字段提供完整的只读任务图模板。狗窝角色把所有明确指定成员的任务交给 TaskGraph，包括只有一个只读节点的任务。狗子 ID 只用于节点的 `operator.preferredIds`；直接执行工具在执行前拒绝这些 ID，并说明正确派单路径。图校验错误仍是图校验错误，需要修正所指出的字段。连接状态不能证明原生执行提供方已通过资格检查，也不能证明任务完成。

## Alternatives considered

**在宿主工具注册表注册狗子。** 直接执行缺少成员要求的 TaskGraph Attempt 和执行授权。由调度器负责准入和验收，可以保留这一要求。

**自动补齐缺失图字段。** 推断工作区、权限或验收条件会增加模型未提交的权限。完整模板提供构造指导，同时校验仍拒绝不完整输入。

## Consequences

指定成员的工作保留持久化调度和执行授权，错误的直接调用在产生副作用前失败。稳定工具描述增加提示词 token。模型指导和无额度回放不能保证实时模型一定构造正确任务图，也不能证明已安装版本健康。

## Verification

局部图测试用实际校验器验证模型可见模板，并拒绝缺少标题的输入。真实组装的无界面应用快照固定模型收到的 schema。直接执行工具测试覆盖派单前拒绝，真实成员进程测试在不调用付费模型的条件下覆盖 TaskGraph 路径。
