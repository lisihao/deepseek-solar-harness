# Agent Note: 领养前验证狗子项目

Status: implemented

[English](2026-10-04-gouzi-project-validation.md) | 中文

## Problem

本地工作区列表与原生文件夹选择器也会提供普通目录。把这些路径当作可执行仓库，会让用户走到最终领养时才看到 Git 错误；最近使用的普通目录还可能被默认选中。

## Decision

[狗子 UI 拥有者](../../../../packages/orchestration/ui-gouzi/README.md)通过现有宿主仓库解析器检查候选路径，再允许选择。当前执行协议需要带有效 `origin` 的 Git 仓库，不会初始化目录或增加普通目录执行。请求失败不代表项目可用。选择器被替换或卸载后，迟到的检查结果不能更新选择。

领养执行器在配对宿主或创建成员之前再次解析所有请求路径。明确的仓库或路径拒绝以 `GOUZI_PROJECT_UNAVAILABLE` 返回，并指出出错路径和仓库要求。非预期进程和传输失败仍作为请求失败报告。不增加宿主服务方法或新的编排权威。

## Alternatives considered

**初始化每个选中的目录。** 这会修改用户项目并凭空补造仓库 origin，而无法建立当前协议需要的执行身份。

**领养时信任选择器检查。** 项目内容和远程地址可能在检查后改变，直接 HTTP 调用也能绕过选择器。

## Consequences

用户在确认之前得到具体项目原因；默认选择只使用已检查可用的候选。普通目录仍不支持。领养时仓库可用并不保证后续任务可以重现有改动或未提交的输入。拥有者 Host 与浏览器测试覆盖拒绝、没有创建副作用、检查未完成和迟到结果；真实产品组成仍是独立的验收要求。
