# Agent Note: ChatGPT Web ephemeral 对话隔离

Status: implemented

[English](2026-09-08-chatgpt-web-ephemeral-conversation-isolation.md) | 中文

## 问题

ChatGPT Web 算子会在多次调用之间复用同一个已认证 Ego Lite 工作区。为配置的根地址选中的页面可能已经属于较早的 `/c/...` 对话，因此新的独立物理算子请求可能被追加到不相关的网页上下文中，即使 DSH 会话日志只记录了当前用户消息。

## 决策

每次 ChatGPT Web ephemeral 调用都会在选择工作区和标签页后，明确丢弃选中页面，并打开一个位于配置的 `https://chatgpt.com/` 根地址的替代页面。可信浏览器程序会先确认页面位于根地址且用户轮次与助手轮次均为零，再标记输入框或填入任何文本。若页面仍保留较早轮次或停留在其他路由，程序返回 `context-not-isolated`；Service Provider 将其映射为 `CHATGPT_WEB_CONTEXT_NOT_ISOLATED`，且不会提交内容。

已认证命名工作区可以继续复用，但 ChatGPT 对话不能复用。一个 DSH 会话可能包含互不相关的用户目标，因此不会被当作一个 ChatGPT 任务。ephemeral 调用仍只发送当前物理算子请求中的任务内容。

## 考虑过的替代方案

**在整个 DSH 会话中复用当前 ChatGPT 对话。** 这种方案保留隐式追问，但会把 DSH 会话当成未经验证的任务边界，并再次造成跨目标上下文污染。

**每次调用都创建一个 Ego Lite 工作区。** 这种方案同时隔离标签页和浏览状态，但会不断累积任务空间并重复生命周期清理；一个命名工作区已经可以复用认证状态。

**打开带随机标识的 ChatGPT URL。** 这种方案可以降低精确 URL 被复用的概率，但 URL 规范化仍取决于网站和浏览器辅助程序。丢弃页面并检查替代页面的路由，可以在提交前直接证明隔离条件。

**把选中页面导航到根地址。** 持有活跃对话的页面可能挂上 `beforeunload`，而 v1 浏览器接缝不提供对话框控制，因此这次重置导航会阻塞在 Service Provider 的 CDP 客户端里，直到该请求超时并使整次调用失败。关闭页面可以在不触发卸载提示的情况下释放其文档，且无需新增接缝能力。

## 后果

独立 DSH 请求不会再通过浏览器复用继承较早的 ChatGPT 对话。在未来的持久 Service Provider 持有 ChatGPT 轮次身份之前，显式追问必须作为包含所需上下文的完整独立请求提交。已有 ChatGPT 对话仍保留在账户历史中；隔离的 agent 任务空间会复用认证状态，只关闭选中的页面，而不关闭浏览器或工作区。

单元测试会在初始选中已有对话的情况下执行可信浏览器程序，验证页面丢弃与其替代页面先于提示填入，并验证重置失败会阻止全部 `fill` 与 `send` 操作。Service Provider 测试固定公开失败代码，并确认进度记录不包含提示词正文。
