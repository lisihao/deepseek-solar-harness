# Agent Note: 每个成员任务里的角色目标和用户备忘

Status: implemented

[English](2026-10-14-gouzi-member-profile.md) | 中文

## Problem

狗窝成员收到的只有名字。领养时选的角色（研究、开发、测试等）不影响成员做什么，因为每个角色模板的一句话目标只存在于浏览器里，也没有地方告诉某只狗该怎么工作。用户希望每只狗带上个性和长期偏好，就像其他产品里的机器人那样。

## Decision

[成员](../../../../packages/orchestration/orchestration/src/gouzi.ts)带一个可选的 `profile`：用户写的备忘，1 到 2000 个字符且不含控制字符。`adopt` 和 `edit` 接受它（`edit` 用 `null` 或空白文本清除），向导的角色步骤和编辑表单提供文本框。

狗窝成员收到的每个任务都以 `kennelMemberBrief` 开头：成员是谁、角色模板的一句话目标（`GOUZI_ROLE_GOALS`，浏览器那张表由一个 Host 测试与它绑定；`custom` 角色不写目标），以及作为风格和偏好引用、不改变任务范围和限制的备忘。它对聊天、读取、写入、[评审和返工](../../../../packages/orchestration/kennel-review/README.md)任务一视同仁，所以备忘不会只到达部分任务。文本在主实例上生成，远程成员不需要升级。

任务必须能从会话日志复现。[调度器](../../../../packages/orchestration/ui-gouzi/README.md)把每个被提供成员的备忘作为 `profiles` 快照进 `kennel/dispatch-request` 事件（没有成员带备忘时不写这个字段），并在被选中成员的备忘于决定之后变化时拒绝启动，与它对模型变化的处理一致。协作候选在记录的 `members` 里带着成员的备忘，返工从已记录的候选取备忘。备忘不进入调度模型看到的内容，包括协作候选里的成员，因为它们会让每个候选各占一份输入，而且不属于选择成员的依据。

存储是 state schema 7 新增的可空列 `gouzi_members.profile`。首次迁移到 schema 7 之前，存储会把状态文件复制为 `state.sqlite.before-schema-7`，并且不覆盖它。

## Alternatives considered

**把备忘放进每个工作候选。** 候选按成员、项目、模式各一份，日志事件会把 2000 字的文本重复几十次，调度输入也会超限。每个请求一张映射表同时避免这两点。

**经授权或成员协议发送备忘。** 这会把功能绑到成员的版本上，旧版本的成员（比如 Mac mini 上的 3.36.0）就用不了。任务文本本来就由主机来写。

**不为这一列升 schema 版本。** [成员模型的 Agent Note](2026-10-08-gouzi-member-model.md) 已经定过：旧程序会写出不带该设置的成员，所以已发布的状态需要明确的带版本的失败。

**狗子从自己的工作里学到的记忆。** 成员的回复没有写进会话日志，没有可学习的素材；而无法从日志重建的记忆会违反"模型可见输入必须记录"的规则。本说明只覆盖用户自己写的内容。

## Consequences

现有成员现在每个任务都会收到它的名字和角色目标，这会改变它们据以工作的文本；没有备忘的成员不会多出备忘行。schema 7 迁移是单向的，与 schema 5、6 相同：保留的 3.42.2 应用备份不能再打开迁移后的狗窝数据库，手动回滚要用 `state.sqlite.before-schema-7` 这份副本恢复。任务里的角色目标是固定的中文文本，改动模板需要同时改两张表。

备忘是用户自己的文字，会发给成员的模型；成员的运行环境仍按原来的权限和限制执行，备忘不能放宽它们。已安装产品里真实成员的行为，以及 Desktop 的 `gouzi-e2e`，随发布验证，不在本说明的范围内。
