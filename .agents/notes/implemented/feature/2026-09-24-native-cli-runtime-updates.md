# Agent Note: Qualify native CLIs by required protocol and update them from DSH

Status: implemented

English | [中文](2026-09-24-native-cli-runtime-updates.zh.md)

## Problem

Resident qualification pinned Codex to one SHA-256 of its generated app-server schema and Claude Code to one exact version. The Codex schema digest changes with every release: `0.149.1`, `0.151.0`, and `0.156.1` each produce a different digest, while Desktop already ran against a `0.149.1` daemon whose digest did not match the pin. The exact pins therefore rejected every newer CLI regardless of whether DSH could use it, and DSH had no way to show that a newer CLI existed or to install one.

## Decision

Codex qualifies when the protocol schema generated by the binary the app-server daemon runs declares every method the Resident wire sends or handles. `CODEX_APP_SERVER_METHODS` in `dsh-subagent-codex` lists those methods, and a test keeps the list equal to the method literals in `wire.ts`. Claude Code qualifies on the baseline `2.1` release line at or above `2.1.239`, because the compiled Agent SDK targets that line.

`ResidentOperatorService` gains optional `cliRuntimes()` and `updateCli(product)`. The local Provider downloads the newest platform-native package from a configurable npm-compatible registry, verifies its sha512 integrity, and qualifies the candidate before switching. A Claude Code candidate becomes a DSH-managed copy under `<dshHome>/runtimes`, selected by a wrapper the Resident daemon places first on its PATH; commands resolve per call, so activation needs no restart and the system installation stays unchanged. Codex execution uses Codex's shared app-server daemon, which serves the package Codex manages, so a qualified Codex candidate is activated through Codex's own `app-server daemon update`. The Resident panel shows running and newest versions and offers the verified update to the loopback owner.

## Alternatives considered

**Re-pin the digest on every release.** This keeps an exact guarantee but blocks each Codex release until DSH ships, which is the failure this change removes.

**Run a DSH-private Codex app-server.** This would isolate the Codex version from the owner's installation but requires a separate daemon, login state, and transport; the shared daemon is where Codex keeps persistent threads.

**Install through npm.** Both products publish platform packages whose native binary runs without Node, so downloading one verified tarball avoids depending on npm or Node being present on a Finder-launched Desktop.

## Consequences

- A Codex release that removes or renames a required method is refused with `PROVIDER_VERSION_MISMATCH`, and the update reports that DSH adaptation is required. A release that changes request fields without renaming a method still passes this gate and fails at run time.
- A Codex update interrupts running Codex work and also moves the owner's standalone Codex installation.
- Claude Code outside the `2.1` line is refused until the SDK baseline moves.
