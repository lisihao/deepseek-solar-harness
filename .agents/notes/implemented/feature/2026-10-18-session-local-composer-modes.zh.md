# Agent Note: 当前会话的输入框模式选择

Status: implemented

[English](2026-10-18-session-local-composer-modes.md) | 中文

## Problem

模型菜单会改变部署默认值。对话模式控件需要选择既有 ChatGPT Web 路由并恢复确切的普通模型，同时不改变其他会话。空白会话即使尚无模型请求，也必须在重启后保留选择。回复丢失时，Host 路由可能与浏览器最后确认的显示不同。

## Decision

对话骨架在输入框下方持有会话级列表 slot `conversation.composer.controls`。模型选择插件在其中提供互斥的普通对话／ChatGPT 控件，以及带明确不可用文字的禁用洞察选项。控件共用既有会话目录和模型选择 RPC。ChatGPT 使用既有裸 Web 算子路由，即使发现目录仅公布带冒号的具体模型行也可选择。

RPC 的 `persistDefault: false` 选项只改变当前会话。required-on-read 的 `session/model-selection` 事件保留完整提供方／模型／推理强度，以及已知普通选择或明确的 null。Host 等待会话落盘成功后才返回成功。这类会话后续的模型菜单选择也追加记录，避免重启后恢复旧模式。会话格式仍为 0；不认识此必读事件的读取器会拒绝该日志。解析顺序及失败行为由 [Host README](../../../../packages/host/apiproxy/README.md) 定义。 当前 Host 在浏览器目录更换期间保留未确认落盘标记；新目录从 `session.models` 恢复发送阻止，直到明确重新选择成功。

浏览器以最后一次 Host 确认的路由回显；运行中的回合禁止模式切换，切换中或失败时阻止发送。RPC 失败不能证明 Host 未改变路由。因此，失败后重新选择当前已勾选模式仍会发送新的选择 RPC；浏览器不能只比较陈旧值就清除失败。普通模型历史未知时，用户必须从模型菜单明确选择。

首次目录读取尚未确定当前路由时，读取失败会保留模式选项的禁用状态，显示具体错误并提供手动重试。重试只读取同一 Host 目录，不选择路由、不提交消息，也不能清除尚需明确确认的模式错误。读取中或会话／输入状态不允许交互时，重试按钮禁用。已有模式已知时，仅建议目录刷新失败不会令该模式不可用。

## Alternatives considered

**每次模式点击都改变共享默认值**会意外改变其他会话。仅会话选项保留普通模型菜单行为。

**仅在浏览器保存模式标志**可能在重连、重启或丢失回复后与下一次实际请求不同。选择由 Host 状态和持久会话记录持有。

**等首次请求头再记录**会丢失空白会话的意图。独立的仅日志事件记录选择，不伪造请求或提示词内容。

## Consequences

真实 JSONL 回读及新 Host 实例验证发送消息前的恢复。真实 Host 请求组装验证 Web 路由和普通推理强度的精确恢复。失败用例覆盖路由变更后回复丢失或落盘失败。构建后的浏览器重放验证输入框下方选项、互斥选择、刷新和洞察禁用，同时会话日志没有模型请求。fake 目录避免真实网站或模型调用。这些检查不证明账号可用性，也不安装 Desktop 构建。
