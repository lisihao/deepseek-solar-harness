# Agent Note: 确认后的狗子目录领养与项目直接执行

Status: implemented

[English](2026-10-06-gouzi-directory-adoption.md) | 中文

## Problem

用户选择的项目可能包含未跟踪内容、尚无 Git 提交，或没有 origin。要求发送端仓库干净且已提交，会阻止成员在所选目录工作，并可能以克隆快照代替实际项目。用户仅打开选择器时，检查不得修改目录。

## Decision

[Host 领养执行器](../../../../packages/orchestration/ui-gouzi/README.md)接受已有目录。`resolveRepository` 只读。确认领养后，系统再次检查全部选择和成员容量，才按顺序调用 `prepareRepository`，并按已解析 source 去重。准备只为 Git 仓库之外的目录初始化 Git；不暂存文件、不提交、不创建 origin，也不修改既有 origin。准备失败不会创建成员或配对宿主，也不占用名额。响应列明已完成的准备；保留其中的元数据，不删除可能已被共享的 `.git` 目录。

每个 `GouziProjectSource` 以确切选中目录的真实路径作为 `source`，以该路径的 SHA-256 十六进制摘要作为不透明的 64 字符 `projectId`，并将规范 origin 作为可选的信息字段 `repository`。确认页明确标记第一个选中项目为默认项目。成员配置会在集群配置中持久化项目映射与 `defaultProjectId`；按项目身份去重时保留第一个选中的 source。

[目录执行](../../../../packages/orchestration/orchestration-local/README.md)使用版本化的 `gouzi-project` 工作区身份，包含项目 ID 和可选相对子目录。接收成员只通过已注册项目映射解析它，并在该选中目录执行。执行必须挂载成员 service，并提供绑定成员身份、generation、权威纪元与请求 hash 的授权。发送端绝对路径、伪造仓库身份和虚构 commit 都不能授予访问权。普通远程 Git 执行保留干净精确提交的物化与独立 checkout 语义。

共享目录锁与命令回执位于用户项目之外。并发冲突执行和过期但未解决的锁会拒绝复用；结算释放元数据而不移除用户文件。未知命令结果需要核对，不能自动重放。Remote Sync 执行使用协议 1.5，SSH Gouzi agent 使用协议 2；不兼容远端 agent 会明确失败。本源码变更不部署远端安装。

本决策取代[项目检查记录](../bug-fix/2026-10-04-gouzi-project-validation.md)中的 Git/origin 限制，同时保留只读检查、过期结果栅栏和执行器再次校验的依据。旧记录保留为先前执行限制的历史说明。

配置了项目的成员在持久化的默认真实目录执行；仅配置 repositories 的成员保留干净精确提交的 Git 物化及相同授权检查。目录命令的相同进行中请求共用一次准入。恢复在资格检查之前读取持久化的原生命令回执：已有回执时恢复原 turn 与当前 revision，不再次 execute，即使资格不可用或成员记录接受状态失败。`inspectWorkspace` 只读持久化租约。存在租约但没有原生回执时结果为 indeterminate。关联的 `ResidentCommandRefusal` 加上成功查询确认没有回执，才释放该租约；未知传输结果和检查失败会保留它。查询时刻没有回执不能排除先前请求仍在准入中。必需的 `command.inspect` 能力保持协议 v14/schema6 不变；缺少它的旧 daemon 会明确失败，不扩大自动退休规则。

## Alternatives considered

**要求干净且带 origin 的 Git 仓库。** 该条件适合可复现的远程快照，但排除了用户为成员明确选择的普通、未提交和无 origin 目录。

**浏览或检查时初始化。** 查看候选目录或取消向导不等于确认领养。全部路径与容量通过后才准备，可以防止这些读取修改项目。

**克隆快照或为目录执行伪造 commit。** 克隆遗漏未跟踪和未提交内容，虚构 commit 则错误表示执行输入。明确的项目身份记录目录执行，不改变普通远程 Git 语义。

**后续失败时撤销先前的 Git 初始化。** 外部并发修改后，准备过程无法安全断定自己独占元数据。保留并报告已完成准备，可以保护用户文件并如实呈现失败。

## Consequences

成员在可变的选中目录工作，其输入不是不可变 commit 快照。共享目录锁串行化冲突命令，主实例仍持有调度与授权权威。准备失败可能在先前选中目录留下 Git 元数据，但不会留下已创建成员或占用名额。启动已配置成员仍是独立生命周期步骤，其失败保留 provisioning 状态。

Host 聚焦测试覆盖普通与无 origin 选择、只读检查、后续路径无效、准备前容量拒绝、准备失败不创建成员、部分准备报告、去重和使用已准备结果配置成员。跨 Provider、协议、组成应用和安装态验收属于独立证据；Host 测试通过不能证明这些验收完成，也不代表已部署。
