# Agent Note：狗子 SSH 主机经 Tailscale 连接

状态：已实现

[English](2026-10-11-gouzi-ssh-over-tailscale.md) | 中文

## 问题

SSH 主机只能按用户输入的地址直连，`ssh-keyscan` 和 `ssh` 都是直接连接。在家庭局域网里添加的主机（`192.168.2.200`）换了网络就连不上，而同一台机器经 Tailscale 能连通，主机密钥也相同。主机不能修改，而上面还有成员时又不能删除，所以这样的主机和它的成员一直连不上。

## 决定

主机有一个可选的路由 `{ via: "tailscale", socket? }`。走路由的连接把 Tailscale 命令行当作 `ssh` 的 `ProxyCommand` 运行（`<命令行> [--socket=…] nc <地址> <端口>`）。`host-route` 修改已有主机的地址、端口和路由；只有新地址上的机器出示的密钥与已登记的一致才接受，所以主机保持原来的身份，成员也留在原处。新连接先用远端 agent 验证通过才保存，该主机成员的端口转发会先关闭、等待结束，再经新路由重开。

请求只能指定 socket 路径。命令行程序来自 Desktop 配置里的 `ssh.tailscale`，否则依次查 `/opt/homebrew/bin`、`/usr/local/bin` 和 Tailscale 应用；都找不到时错误信息会列出试过的每个路径。从图形界面启动的应用 `PATH` 很短，所以从不依赖裸的 `tailscale`。

`ProxyCommand` 由 shell 执行，`ssh` 还会展开其中的 `%` 标记，所以地址和端口直接写入（不用 `%h`/`%p`），每一段都经 shell 引用，socket 只允许 `[A-Za-z0-9._/+@~=-]`。cockpit 和 admin 设备都能调用控制动作，自由文本命令或请求指定的程序就等于在主 Mac 上执行命令。

走路由的连接忽略用户自己的 ssh 配置（`-F /dev/null`），所以那里为同一地址写的别名（例如 `HostKeyAlias`）不会改变所查找的已登记密钥。`ssh-keyscan` 不支持中继，所以走路由时让 `ssh` 做到密钥交换并把看到的密钥记在临时文件里读取；该文件里的那一行就是登记的密钥，名字与之后连接查找的一致。

## 考虑过的其他方案

**每台主机一个自由文本 `ProxyCommand`。** 能适配任何代理，但任何管理设备都能执行任意命令。已拒绝；以后要加别的中继，就新增一种带自己校验的路由类型。

**删除后重新添加主机。** 上面有成员时做不到，而且会让成员退役。

**不比较密钥就信任新地址。** 这会让改地址把成员挪到另一台机器上。已登记的指纹就是身份。

## 影响

只要 Tailscale 在运行，主机在任何网络下都能用。Tailscale socket 路径随主机保存。走路由的首次连接经中继可能要几秒，所以连接超时是 25 秒而不是 10 秒。连不上 tailscaled 时报告"Tailscale 没有运行，或者 socket 路径不对"。

验证用的是真实的 `sshd` 加一个会中继并记录参数的替身命令行。在真实的 tailnet 上只比较了主机密钥（mini 经中继的密钥与已登记的一致）；经 Tailscale 唤醒成员需要装有本次改动的安装版本，并且那台机器的 DSH Desktop 仍要支持当前的 agent 协议。
