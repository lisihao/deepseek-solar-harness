# Agent Note: Task-scoped template context

Status: implemented

[English](2026-09-08-task-scoped-template-context.md) | 中文

## Problem

同一会话可以包含互不相关的任务，执行也可以在原生模型与物理算子之间切换。以整个会话历史作为模板选择上下文，会把前一任务的指令带入新任务。重复注入同一模板也会增加上下文体积，却不能证明实际影响执行的是哪个版本。

## Decision

模板选择归属于逻辑任务，即当前尚未结束的 Agent 轮次的发起请求。新轮次重新选择模板。选择回执被记录到日志并附在注入消息的来源字段上；模型可见载荷固定所选模板的标识、版本、摘要和渲染内容。仍保留的上下文直接复用；若压缩在同一未结束轮次中遮蔽该上下文，则使用已记录回执最多恢复一次完全相同的固定内容。轮次结束后的后续请求不会恢复前一任务的选择。继承的父任务上下文不会抑制委派任务自己的选择。

物理算子通过既有 OperatorContextEnvelope 传递模型可见的任务上下文。每个 Consumer 返回独立的、绑定摘要的上下文回执，Resident 请求身份包含 NativeContext。对该独立回执的校验检测上下文丢失或变化。本决定改变上下文准备方式，不改变供应商凭据或执行权限的所有权。

## Alternatives considered

**按整个会话复用模板。** 这混淆了任务身份与承载它的会话，无法安全区分无关的后续请求。

**每次请求重新注入。** 重复会增大上下文，不能替代明确的版本归因或压缩恢复。

## Consequences

执行消费者必须保留任务身份，并区分选择回执与物化回执。回执支持归因，不证明回答质量，也不授予额外工具、文件访问或外部写入权限。个人模板与偏好内容属于私有运行数据，不属于可发布的测试样本。
