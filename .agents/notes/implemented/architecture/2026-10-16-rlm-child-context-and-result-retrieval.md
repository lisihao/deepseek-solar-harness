# Agent Note: A child starts with its own context, and a parent reads a child's result in checked segments

Status: implemented

English | [中文](2026-10-16-rlm-child-context-and-result-retrieval.zh.md)

## Problem

A child's REPL `context` was a clone of its parent's `context`, whose `task` is the parent's whole task and can hold the whole input and the tasks of other children. The captured requests show three different places where this appeared.

1. **The child's initial request**, on both paths, carried only the child's own task. It was not affected.
2. **The child's later API requests.** The model worker returns the result of each cell to the model as a tool message in the next request of the same loop. The child's cell `JSON.stringify(context)` therefore came back to the **child**, in its own requests of rounds 1 and 2: a marker that appeared only in the root's task, and the root's last line, were in the child's request body. The root did not receive this result.
3. **The Resident child's REPL.** The same cell printed the root's task. This is a cell result, not a field of the request the daemon sends to the ResidentClient, so the Resident request capture does not contain it; the cell result is recorded separately.

That the initial prompt held only the child's task does not show that the child's later model requests were unaffected: they were not. This is a visibility leak between agents. The cost and the answer quality it caused, and the effect of fixing it, have not been measured.

A parent also had no bounded way to read a child's stored result. `listSubagents()` dropped `outputPreview`, and the full result existed only as an artifact the model could not name; the parent saw only what the child chose to message. Nothing here measures how often a larger result mattered; this note records the contract, not a gain.

## Decision

**A new child's `context` is the protocol keys of its parent plus `task` set to the child's own whole task.** The protocol keys are `runId`, `nodeId`, `contextPacketRef`, `capabilityPlanRef`, `graphCertificateHash`, `defaultChildOperatorId`, `defaultChildModel`, `defaultChildTier`. Nothing else is copied: not the parent's task and not values its cells stored. Trusted child selection (model, policy) is read from the persisted session snapshot, not from `context`, so no decision depends on the dropped fields; a child that needs material gets it in the task its parent writes. The task is never shortened. Children admitted earlier keep the `context` they were persisted with; an old child `context` is not migrated or rewritten.

**`rlm.childSummaries()`** returns id, name, depth, lifecycle, `resultRef`, `error`, and `preview`: the first 200 UTF-16 code units of the `outputPreview` the child's record holds, which is a preview recorded when the child ended and not a guaranteed prefix of the full result text. It omits the task and session directory. `listSubagents()` is unchanged.

**`rlm.readChildResult(child, { offset, limit, resultRef })`** reads one segment of a direct child's stored result. Authorization comes first and from the caller's persisted record: the child must be one of the calling session's children (`RLM_FAMILY_VIOLATION` otherwise), a given `resultRef` must be the one recorded for that child (same error), and a deleted or closed child is `RLM_UNAVAILABLE`. A child that is accepted or running is `not_settled`, an indeterminate child is `indeterminate`, a child without a result or whose result the host does not hold is `not_found`; none of these is returned as an empty success. The daemon's reader then returns the stored content for the recorded reference only if it is a `prime-rlm-child-result` of the same run, node and child session, and checks the fields of such an item: a non-empty execution id, one of the five stop reasons, and output blocks whose fields have their types (a text or reasoning block has a string `text`; a block of a type this build does not know is kept and counted as not text). The artifact store checks that the content matches its reference, not that its fields are valid, so a damaged item that is this child's result throws `RLM_UNAVAILABLE`; it is not rendered, and not reported as missing or empty.

The rendering is the text blocks joined by one newline; blocks that are not text are counted in `omittedBlocks` and not rendered. Units are UTF-16 code units; a segment never ends inside a surrogate pair, and an offset past the end or inside a pair is `RLM_INVALID`. The result carries `segmentSha256` (the segment), `fullSha256` (the whole rendering), `resultRef` (the artifact reference, which is a different hash), `totalUnits`, `complete`, `truncated`, `nextOffset`, `stopReason`, `commandId`, `isData: true` and the text. The object is kept within one third of `limits.maxOutputBytes` because the cell's recorded output counts both the value and its rendering. A read that returns a segment appends `rlm.child.result.read`; the `not_settled`, `indeterminate` and `not_found` results and the errors append none. `readResult` is an optional host binding; without it the helper fails with `RLM_UNAVAILABLE`.

**The generic strategy text changed in its own commits** (strategy `1.5.1`; the set is `06d55d6ff6` for the first wording, `0e90ada770` for its tests, `23f582a2d9` and `cdb78006ec` for the snapshot hashes, and `fd202d16e0`, which makes the advice conditional; reverting the wording needs all of them and the matching `strategy.spec.ts` lines). The advice to create no child is the default only when the task does not explicitly ask for a division of work; an explicit request is followed within the child, depth and turn limits and the sealed capabilities, in both fidelities. It adds no field to the plan and no `delegation` setting.

## Alternatives considered

**Keep the parent's `context` and hide `task`.** Rejected: values stored by cells would still go with it, and a field-by-field deny list fails open for new keys. An allow list fails closed.

**Truncate a child's task to a tail.** Rejected: the child's own last lines carry its output rules; the task stays whole.

**Authorize by the reference alone.** Rejected: the artifact store is shared by every run. The record in the caller's session names the reference, and the daemon checks what the store returns.

**Return the whole result with a truncation flag.** Rejected: a result can exceed the output limit; segments with two hashes let a parent verify reassembly.

**Treat a block of an unknown type as damaged.** Rejected: the block union is merge-extensible, and the reader already counts every block that is not text as omitted.

## Consequences

The model-visible changes are the bytes of the `typescript_repl` tool description (two sentences naming the new helpers; in the API tool list and in the Resident bridge), the strategy instruction text in the root's request (version 1.5.1), and, for a child created after this change, the child's later API requests, which carry its own context in the `JSON.stringify(context)` tool result instead of the root's. The effect on cache hits, tokens, cost and answers is not measured.

The state file format did not change: the new helper reads the existing `resultRef` of the persisted children, state stays at version 6, and old child contexts are not migrated or rewritten (the state file is otherwise written as before). One persisted record type is new: a read that returns a segment appends an `rlm.child.result.read` event (child, command, reference, offset, length, flags, both hashes, status; no text) to the `events` list of `state.json`. State loading checks that `events` is an array and does not check event types, and 33 distinct `rlm.*` event type strings already appear in the runtime source at the base commit, so a build without this change loads such a file; this was read in the code and not tried on an older build. An auto-refine turn puts the last 128 events of the session into its prompt, so these small records can appear there.

The sealed `rlm-runtime`, `rlm-runtime-local`, `rlm-strategy-local` and `orchestration-local` packages change, so a Desktop release containing this needs them resealed.

## Tests

`child-context.spec.ts` covers the allowed keys, the whole task including its last line, none of the parent's task or stored values, grandchildren, and a persisted session. `child-result.spec.ts` covers reassembly with both hashes over text with surrogate pairs and multi-byte characters, the output limit, every refusal (another session, a guessed reference, deleted child, host without a reader), the status of unsettled, indeterminate, failed and result-less children, ranges, rendering of mixed blocks, summaries, the event, the error of a reader that found a result damaged, and the same authorization after a restart. The restart test creates a new runtime on the same state file and binds the host again; it does not exercise the daemon's or the Resident's own recovery. A child created before this change still shows its parent's task in its `context`, and a test asserts that. `rlm-continuation.spec.ts` covers a stored item of another run, node, child session or kind, and, for an item that is this child's result, a missing, empty or non-string execution id, a missing or unknown stop reason, an output that is not a list, and blocks that are null, have no type, or have wrong field types. `rlm-strategy-local/tests/strategy.spec.ts` covers both fidelities, including a small task that explicitly asks for two children.

**The request captures.** The fake provider keeps each request's exact bytes, sha256, arrival ordinal and the tool call id it answered with. The Loader capture goes through the production Loader, daemon, model worker and adapter to the loopback fake; only the provider is replaced. It ties every request to the session and worker command the runtime recorded, through the tool-call ids and the runtime's cell receipts, cross-checks the tool results against them, and uses the text of a request only as a check that must agree; a request that cannot be tied to exactly one dispatch fails the scenario instead of defaulting to a child. The projection used for the snapshot replaces run-specific values at known places with one indexed token per distinct value, leaves task text, tool schemas and policy text as they are, and fails unless putting the values back gives the raw request. The Resident capture saves every serializable field of the request the daemon sends to the ResidentClient, names the excluded field (`signal`) and why, adds the root's message continuation, and ties each request to the events the daemon and runtime recorded. **Its limit:** it covers the daemon-to-ResidentClient call only, not the native driver's own model requests or tool rounds. The raw files, correlation, projections and the field-by-field comparison are in the evaluation report directory.

**Before and after.** The before capture is commit `a71f5858` with a capture-only patch (the new capture files and the changes to the driver and the Resident test; the patch also makes the continuation run one trivial cell, because a loop that issues no tool call cannot be tied to a production record). The comparison with this change lists every difference, and all are intended: the tool description bytes in every request, the strategy version and instruction in the root's requests, the child's rounds 1 and 2 tool message (its own context instead of the root's), the continuation's second round (reading the result instead of the trivial cell), and the Resident child's REPL `task`.

**Mutations.** The final set has 72 mutation ids; 80 definitions were run over two increments, each breaking one rule (the definitions of N27, N29 and N31 stopped applying when the validation and the strategy wording were rewritten; N27 was redefined and N29 and N31 were retired in favour of the controls of the current wording), over the runtime, the stored-result validation, the strategy, the capture library, the Resident end-to-end seam and the API seam (the production Loader snapshot, source mode). Not detected on first run, and what became of each: the newline join of rendered blocks and the prime-strict strategy wording (closed by tests); the capture checks for a result that names a later request and for a tool schema swapped for a restoring token (closed by tests); a clone-of-the-parent mutation at the Resident seam (replaced: equivalent there, because the child's task is assigned afterwards; covered by the runtime control); a `complete` mutation at the Resident seam (replaced; covered by the runtime control); a segment-hash mutation at the Resident seam, which survived once and was closed by checking each segment's hash and offset; and a mutation that dropped the child-session condition of `childResultFromArtifact` (survived the daemon end-to-end test). For that last one, the changed mutation that makes the daemon pass a wrong child session id is a different control: it first failed the end-to-end test by a 5000 ms timeout and now fails by assertion (`not_found` for `settled`); it shows that the daemon passes the right session id, not that an item of another child session is rejected through the daemon. Rejection is covered by the unit test of `childResultFromArtifact`; **no test makes the daemon read an item of another child session end to end.** The superseded definitions and their logs are kept in the evaluation report directory.
