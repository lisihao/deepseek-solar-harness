# Agent Note: 降低仓库变更的固定成本

Status: implemented

[English](2026-08-22-reduce-unit-change-cost.md) | 中文

## 问题

本仓库的插件、测试、文档与治理纪律保护了真实的产品不变量，但要求每个非平凡变更都编写 Agent Note，会把日常实现历史变成永久的双语架构清单。即使没有形成持久决策，这项成本也会随每次变更继续增长。现行预发布政策还假定不存在已发布消费者或持久产品状态，而 DSH Desktop 已经发布带标签的正式版本。

## 决策

Agent Note 只记录无法完全由代码与当前状态文档承载其依据的持久决策。跨包架构与所有权、公开能力合同、已发布的持久化或协议兼容性、权威与权限规则以及仓库级工程政策需要 Agent Note。孤立修复、既有合同内的实现、重构、依赖更新以及文档或测试维护不需要。只有当现有 Agent Note 所拥有的决策发生变化时才更新它。

达到上述门槛的 Agent Note 继续遵守双语要求。它记录具有长期价值的产品与工程政策，而不是日常实现叙述；因此，减少 Agent Note 的数量比削弱每份保留记录的权威更能降低成本。

无论内部包是否仍使用预发布版本，DSH Desktop 都按已发布产品处理。已发布的磁盘、协议、会话和配置格式必须保留可读取路径、提供向前迁移，或者通过新的决策与测试引入明确的版本化失败。未发布的内部包 API 仍可与仓库内全部消费者一起进行原子变更。

[Desktop 打包源码闭环](2026-08-20-desktop-source-closure.md)独立关闭风险最高的产物缺口：根构建现在会校验密封核心归档中的生成态 `lib/` 字节。包合并、执行词汇合并、二进制历史移除以及 `api-proxy.ts` 拆分仍属于独立变更，因为每一项都会改变运行时或仓库拓扑，需要各自的证据。

## 曾考虑的替代方案

**继续要求每个非平凡变更都编写 Agent Note。** 这会最大化叙述覆盖面，但会让永久决策清单随日常实现量增长，并掩盖维护者真正可能重新审视的少量决策。

**保留触发门槛，但取消中文对侧文件。** 这会减少每份 Agent Note 的文件数，却保留更大的问题：日常工作仍会创建永久架构记录。同时也会削弱重要决策的双语同等访问能力。

**彻底删除 Agent Note。** 代码和当前文档无法保存被否决的备选方案或持久边界背后的取舍，后续维护者会反复重启已经结束的决策。

**在 npm 包达到稳定版本前，继续把仓库视为没有消费者。** Desktop 用户消费的是打包应用及其持久数据，而不是内部 npm 版本标签；这种做法会保留一个已知错误的兼容性前提。

**在同一变更中合并包与执行机制。** 这些改动可以减少长期表面积，但在依赖和运行时证据不足时实施，会用高风险迁移替换可见的固定成本。

## 后果

- 日常变更不再支付双语 Agent Note 三件套及其后续维护成本，除非它确实形成持久决策。
- 保留的 Agent Note 继续保持双语、结构化和机器配对，其权威不变。
- 已发布数据的兼容性不能再以内部包仍为预发布版本为由被忽略。
- 评审者需要判断是否存在持久决策；明确的必需类别让这项判断保持有界。
- 较大的包、运行时词汇、二进制分发和 API Proxy 改造继续作为可见的后续工作，而不是被藏进治理清理中。
