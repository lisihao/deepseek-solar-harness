# Agent Note：原生 fake pilot 回执

Status: implemented

[English](2026-10-18-native-pilot-receipts.md) | 中文

## 问题

手写输出不能证明排程中的对照实际使用了 Worker、完整材料或 Runtime 子结果。最终文本还可能掩盖未决请求或失败单元。

## 决策

装配后的无密钥 Consumer 使用现有 Loader、共同 Worker 工具循环、Runtime 和评估账本。上下文放置与 Host 持有的子调用策略保持独立。完整 map/reduce 试次把每个原始分块交给所属 map Worker，再把经过归属授权完整读取的每份子结果送入根 Worker 的下一次模型请求。各策略保留同一上限和完整来源字节。外置上下文夹具单元明确请求初始 64 字节片段，不宣称读取全文。

独立 Python 读取器关联请求字节、尝试、发送、Worker 命令和 Runtime 持久结果，先从观察派生生命周期和最终原始文本，再调用现有官方控制端评分器。未知请求保留预留，并明确记录其未进入终态评分的原因；缺失执行仍为缺失。校验及新建输出不会执行或重试试次。

## 考虑过的替代方案

手写终态输出可以测试评分器，但不能验证执行。直接在 Worker 内评分会暴露控制端答案，并混合不同职责。因此 Consumer 保留观察，由独立的只读控制端先核验再评分。

## 后果

适配器使用进程内脚本；其请求和用量记录验证集成及记账关系，不证明模型质量、物理 HTTP、token 上限或费用。回执哈希不是独立观察者的签名。完整产物保留在本地，评分报告含控制端专用 gold。source／built 夹具通过或排程 fake 执行均不授予付费启动、外部研究、打包或安装权限。篡改测试在不重放 Worker 的前提下拒绝缺失、重复或不一致的请求及子结果观察。
