# Model handoff

An independent Solar plugin for official DeepSeek Harness `0.2.1-rc.2`. An ordinary native provider/model switch arms a gate before the target model's next request. Before any summary request, the user chooses whether to carry task context or start fresh. Short tasks retain attributed original text without a model call. Longer tasks use GPT-6 luna with zero to three necessary clarification questions, then a confirmed native context checkpoint. The original event log is retained.

`solar-chatgpt-web/chatgpt-web` and `solar-chatgpt-web/insight-analysis` are explicit operator routes. Entering either route creates a fresh operator task without a handoff question or Luna call. This applies from an idle picker and to the first request of a selected operator preset, before that route has produced a request header. The current first-request prompt stays with the AgentLoop and reaches the operator once; it is not cancelled and does not require a second Send. Switching between the two operator routes stays in the same consecutive operator segment.

## Configuration

The bundle adds one Host row, `solar-model-handoff`. Its validated fields are:

| Field | Default | Meaning |
|---|---|---|
| `summaryProvider` | `openai-codex` | Existing registered provider; no account or authentication changes. |
| `summaryModel` | `gpt-6-luna` | Exact provider-owned model ID; absence is an error, never a fallback. |
| `maxInputBytes` | `1500000` | Maximum complete serialized source bytes; no tail truncation. |
| `maxOutputTokens` | `8192` | Requested summary output cap; its reasoning accounting follows the selected provider. |
| `maxHandoffBytes` | `48000` | Maximum confirmed checkpoint bytes; answers are not truncated. |
| `maxSummaryCalls` | `8` | Maximum logical summary calls, including final reduction; bounded 1–32. |
| `verbatimMaxChars` | `1200` | At or below this Unicode character count, carry exact attributed task text without calling Luna. Set `0` to disable this shortcut. |

Only task history enters this process: explicit user messages, model replies, tool results and relevant tool changes, prior task checkpoints, and attributed task notices/relays. Regenerated system prompts, skill catalogs, runtime/time snapshots and automatic memory recalls are excluded. Producer metadata is reduced to attribution instead of duplicating catalog entries or replay state. Source and role remain distinct, including fictional/test framing.

For task text above `verbatimMaxChars`, Luna is called once when the projected history fits. Longer histories are packed at tool-pair-balanced boundaries and reduced with one additional final call. If one balanced unit is too large, its records are serialized into contiguous Unicode-safe text fragments. Every fragment retains its record role, source kind, position and integrity metadata; tool results also retain their call ID and error flag when present. These are quoted historical material, not orphan native tool messages. The final reduction receives deterministic attribution alongside each draft. No original content is truncated.

The UI first offers carrying task context or cancelling into a fresh context, before preparing a provider call. A multi-call plan then asks approval of its complete chunk count and output caps. Exceeding `maxInputBytes`, `maxSummaryCalls`, final merge capacity or the minimum fragment-envelope size fails before any Luna stream starts. A later provider/output failure can still consume completed calls; no automatic extra attempt is made. Waiting and merging human answers make no model call. The actual provider context window is required; a conservative text-byte admission bound plus output reservation and framing headroom must fit. This is not an exact tokenizer count. Images, attachments and unsupported rich content are refused rather than misrepresented as read.

## Use and recovery

Use the existing model picker. If the Session is idle, an ordinary native handoff starts after its canonical selection event. If work is running, the gate waits until the next request for a changed route. Same-route and effort-only changes do not trigger a summary. Initial model choice without a previous routed request does not need an ordinary native handoff.

When returning from a consecutive Web/Insight segment to a native route, the plugin asks two independent native yes/no questions before target dispatch: whether to carry recorded Web/Insight results with their corresponding task questions, and whether to carry the effective task context frozen immediately before the first Web/Insight entry. All four combinations are valid; selecting neither creates a fresh native context. A selected short source uses the existing verbatim path; a long source retains the existing budget and confirmation flow. If no Web/Insight result was recorded, the result choice does not fabricate a successful response. A changed source segment or target rejects a saved choice instead of applying it to different material.

The plugin uses native single-choice question cards. A draft may have zero to three questions, only for unresolved information; clear next steps and constraints must not be asked again. Each necessary question supplies two or three distinct, contextual full-answer choices; pick one without typing, choose the built-in no-addition option, or enter a custom answer when none fits. Choices do not grant permission until selected, and only the actual selected/custom answer enters the checkpoint. Candidate generation requests preservation of existing constraints and no invented facts or permissions; this is a model instruction, not a semantic guarantee. Old saved drafts without choices remain readable. Each clarification is sent as a separate native request, with its overall position in the title. An option-focused Enter therefore submits only that question; the plugin saves its answer before presenting the next one. Resuming a completed draft does not ask already saved questions again. The official Client still owns keyboard focus and handling, which require installed-App verification. Answer any necessary questions, then confirm the preview. The short-task path shows the exact task transcript with no clarification model call. The preview compares task text and proposed handoff using the same Unicode character count, not a full-context token-pressure figure against a different heuristic. A generated summary longer than task text is refused without silent truncation or automatic retry; explicit human additions remain exact. A custom answer to the preview is treated as a complete replacement summary and must be confirmed in the next preview. Choosing **Cancel handoff, start fresh** keeps the selected model and retains old chat records for inspection, while replacing the old model-visible task range with an empty native checkpoint. It does not carry the rejected summary or old task messages and does not call Luna again. An idle picker change sends no new message; a subsequent user prompt is the new task. An already queued new prompt remains owned by the normal AgentLoop. Future handoffs respect this explicit fresh boundary and cannot resurrect pre-reset raw history.

`/handoff status` shows the current phase without a model call. `/handoff fresh` explicitly starts the selected route with no old task context, including recovery from a prior failed receipt; it makes no model request. `/handoff retry` explicitly permits one new summary attempt; it does not itself run it. An interrupted or unknown Luna request is never automatically repeated. After a lost Client connection, a stored completed draft/answer may be offered again when the changed route is next requested. Unsubmitted question draft text has the standard Client's own persistence limits.

## Data and composition

Private versioned receipts live under `$DSH_HOME/solar/model-handoff/`, one hashed current filename per Session and retained attempt identities under `receipts/`, with owner-only files and atomic replacement. They contain complete summary requests, output and human answers and must not be published. A separate versioned `routes/` receipt stores an operator-entry boundary, frozen effective record references, selected return target and return choices; a replacement summary receipt cannot erase that route state. Each entry and return transaction has its own receipt identity, so an old empty checkpoint for the same native route cannot satisfy a later return. Canonical model-visible content is also recorded by the native `compaction/start`, `compaction/summary`, replacement `user/message`, and `compaction/end` transaction. Generic source collection reads the current effective surface and prior task checkpoints, never an unrestricted scan of shadowed raw events. The only exception is an explicitly frozen pre-operator or selected operator scope, which names exact canonical message records and is fingerprint-checked before use. A log-only failed or unknown operator attempt contributes only visible text, requested tools, and terminal error/unknown facts; its reasoning, usage and replay metadata stay only in the canonical log. Existing prompt/tools/runtime envelope and a newly submitted prompt remain outside the replaced historical range.

The plugin loads a manual `CompactionEngine` implementation in a public Cordis `compaction` isolation realm. The official preset's automatic backend remains unchanged. Both engines honor the native Session compaction lock. Short tasks use a model-free verbatim path; only structural role labels and the handoff heading are added. Long generated summaries cannot exceed their task transcript length. Human additions are separately explicit. No tokenizer savings or semantic-quality guarantee follows from this policy. It uses public Session Query reads and `SessionStore.flush`, not deprecated synchronous Session reads, private provider methods, DOM interception, or upstream patches.

The native summary record uses an unmarked, versioned backend trace in `compaction/summary.rawOutput`, with each exact request, raw output, call identity, finish and reported usage. One-call summaries also carry that request's reported usage at the usual top level. Multi-call summaries do not pretend to be one native LLM call or attach a fabricated aggregate usage. The installed cost meter does not automatically expand this custom multi-call trace; log-rebuilt aggregate counters may omit that usage. Read the individual trace/receipts for it. Missing usage remains unknown; API estimates do not establish subscription quota consumption or net savings.

## Verification boundary

Development checks use fake providers and scratch homes. Build, strict types, unit/runtime tests, built-package profile tests, and installed-App checks are reported separately in the task receipt. The route-policy tests cover idle Web and Insight entry, no-header first-request Insight entry, all four native return choices, absent Web output, receipt replacement, and effective-surface exclusion. The built CLI probe drives a real AgentLoop with fake providers and checks that the first Insight prompt reaches the operator once without Luna. A fake-provider pass does not establish real Luna availability, semantic summary quality, or net token savings. Real model evaluation requires cost authorization. Installation does not rebuild or modify the official App.

The browser bundle uses the published DSH `factory(require) → exports` contract and creates its CommonJS `module`/`exports` inside that factory. Its built-client regression calls the factory with only `require`, reads the returned `apply`/`inject` exports, and exercises the input guard lifecycle. This covers the packaging failure that previously left the web entry inactive; it does not replace installed-App verification.

### Preparing-state input guard

The browser contribution observes this plugin's namespaced native `compaction/start` and `compaction/end` transactions through the existing Session Controller event source. Before any provider wait the Host flushes the start marker. While a transaction is open, the public `conversation.blocks` interface locks the normal editor, Send and Enter submission without changing the draft; an input dock notice says that context is being prepared. Native clarification and confirmation cards remain usable. Completion, cancellation and handled failure release this plugin's block; navigation and plugin disposal unsubscribe and clear only its own block. Other plugins' blocks are preserved. Loaded event replacement and reconnect rebuild from the authoritative window. An unmatched start remains blocked rather than guessing that an interrupted transaction succeeded. The model selector remains available to switch back.

This UI is an affordance after the Host event reaches the Client, not a substitute for the existing Host target-request gate. It does not promise zero transport latency after a picker click. The original session journal remains complete. Rendered default/narrow layouts, actual keyboard behavior and draft preservation in the installed App require human acceptance; source and keyless tests alone do not establish those results.

The status notice is horizontally centered within the conversation column using the normal composer width, with narrow-width padding. Its **×** button has an accessible close label and hides only this notice; it neither cancels preparation nor releases the input/Send block. Dismissal survives navigation within the current plugin lifecycle for that transaction and phase. A new handoff or a transition from preparing to an error/fresh result can show a new notice. This does not change the official question-card renderer.

## Repair acceptance status (2026-10-21)

The short Lighthouse reproduction exposed input-scope bloat, duplicate catalog provenance, a mistaken attribution, incomparable token figures, and the old cancellation policy. These are delivery regressions, not evidence of provider network or quota causation. The repair passed the repository gate: 157 source tests, 25 built-runtime tests, strict types, build, both official CLI scratch-profile probes and the generated homepage check. The real AgentLoop fake-provider probe covered both idle and active cancellation: zero summary/target calls on cancellation, a committed fresh checkpoint, and admission of the next new task without old task content. Restart coverage rejects an expanding completed final receipt without replay; checkpoints remain labeled as historical summaries rather than user speech.

A private offline replay of the actual Lighthouse log projected 13 source records into the six task messages: 315 body characters, or 338 characters with source labels. This falls below the default 1200-character verbatim threshold and needs zero summary calls. The fictional framing remains literal user text. No private session material is included in the repository. Installed-App acceptance and exact remote CI for this repair remain pending until recorded in its delivery receipt. No new live-model test is authorized or implied.
