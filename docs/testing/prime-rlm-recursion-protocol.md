# Native recursion ablation pilot

Date: 2026-10-21, Asia/Shanghai. The latest direct user instruction authorizes a new S/S0 comparison under the unchanged cumulative 522-request cap. The completed ARC panel remains unchanged.

## Observable acceptance

Execute two fixed paired tasks once, using original Prime through the same compiled Solar host: S allows root-to-child depth one; S0 uses native depth zero. Compare independently graded answers and observed child use. Every request, including descendants, counts against the same 14-request tree allowance and 56-request new-panel maximum. With 463 retained charges, planned cumulative maximum is 519, below 522. Engineering success, completed output and quality benefit remain separate claims.

## Fixed tasks and controls

The pinned OOLONG MultiNLI windows 70016 and 70017 each contain 438 sentence pairs. Q02 requires all semantic labels and their counts. Q03 requires those same outputs plus every user pair satisfying the public count constraints. Labels are private; public inputs contain the original sentence-pair text with new record/user identifiers. Ordering and assignment depend only on a private random salt, never on gold labels. These are custom dense-aggregation queries, not exact reproduction of the original paper benchmark. The paper's [REPL/no-subcall ablation](https://arxiv.org/html/2512.24601v1#S2.SS2) motivates this comparison.

Within each task both arms receive byte-identical material, task text, answer schema, persistent Python, tool access, model/effort, output limit, wall-clock limit and complete-tree allowance. Factory and Harness refinement/learning are disabled equally. Model choice or thinking overrides in a child are forbidden and all actual provider requests must remain gpt-6.1-sol/high. Native child system instructions, parentage and capability text necessarily differ; their diffs are recorded rather than called identical full prompts. The root chooses partitioning and child prompts; no controller injects a successful decomposition.

Q02 runs S0 then S; Q03 runs S then S0. Every arm starts with a fresh HOME, native session, working directory and state. Recursion-enabled runs must report whether a real child session and child model request occurred, and what input/output it contributed. Zero observed child requests cannot establish recursive-effect evidence. Two pairs are a diagnostic pilot, insufficient for a general or statistically established quality claim.

## Integrity and budget

The previous temporary raw ledger is no longer available in the current environment. Its independently checked aggregate survives in the committed, hashed ARC result JSON: 463 charged = 456 confirmed + 7 unknown. This is an explicit aggregate prefix, not a reconstruction of missing individual request identities. The new durable ledger records new requests in its own namespace and reports cumulative values by adding that unchanged prefix. It must never reset spending or refund unknowns.

New preparation, ledger, markers, request receipts and outputs are kept in a private persistent artifact directory; only owned native process/socket paths use a short temporary root. This prevents another temporary-directory loss from erasing admitted calls. Oracle/source labels, credentials and other arms are outside the native sandbox; public input writes and outbound network are denied. The same parent dispatcher serializes concurrent child requests before physical admission, validates one physical POST per logical request, and admits no fifth condition or fifteenth tree request.

Before real dispatch: validate the independent parser/grader with mutations; exercise the queue and full budget using synthetic requests; run the actual original Prime/Python with local scripted responses to prove depth-zero refusal and depth-one child execution/collection, inherited access to the same material, fixed route, denied oracle/input-write/network access and complete cleanup. Freeze source, plan/input hashes and acceptance receipt. Tests do not load the subscription provider.

Primary scores require a complete valid output schema; missing, duplicate or unknown record IDs fail that gate. Diagnostic accuracy, counts, pair-set correctness, execution status, time and complete-tree resource use remain visible. The grader accepts no arm identity. Preserve ties, wrong answers, resource/transport failures, missing outputs and unknown requests. No repeated sampling until a positive result.
