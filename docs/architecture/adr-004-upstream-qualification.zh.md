# ADR-004：上游变更必须先验收再集成

状态：已接受

[English](adr-004-upstream-qualification.md) | 中文

## 背景

自动发现新的上游 revision，并不能证明它会保留 Solar 会话、工具、插件、profile 或 Desktop 行为。直接合并上游 HEAD 会把“发现更新”变成未经评审的产品发布。

## 决策

自动化可以发现新 revision 并创建候选分支，但不得直接写入 `solar`。每个候选都要记录新旧 revision，把机械导入与 Solar 适配分开，报告冲突与接口变化，并执行完整的受影响能力合同。

纯文档元数据属于 R0，隔离的叶子插件变更属于 R1，会话、Agent Loop、沙箱、持久化、默认插件或 Desktop 打包变更属于 R2。R2 候选只有在完整 Code-as-Harness、CI 和产品验收证据之后才能由人批准。失败或证据不完整的候选保持拒绝状态，不改变已接受 revision。

## 后果

仓库可以持续更新，而不会把“最新”等同于“已接受”。每次接受上游移动都有可评审差异、兼容性证据和回滚点。Agent 可以解决冲突，但同一个 Agent 不能提供 R2 合并所需的人类批准。
